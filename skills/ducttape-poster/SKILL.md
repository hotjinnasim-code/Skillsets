# 덕테이프 포스터

내용을 받으면 **서로 다른 스타일 다섯 개 × 독립된 완성 이미지 한 장 = 총 다섯 장**을 직접 만든다. **스타일의 차이를 우선한다:** 이미지 표현·편집, 색·대비, 타이포그래피의 목소리, 재질·마감과 정서가 함께 만드는 정체성을 현재 내용에 맞게 설계한다. 잘 읽히는 Title·body의 순서와 정렬 구조는 여러 방향에서 공유할 수 있으며 다섯 레이아웃을 전부 다르게 만들 필요는 없다. 축적한 디자인 아이디어, 내용에 맞는 시각적 발상, 카피를 읽게 하는 구조, 이미지와 글자의 마감을 함께 설계한다. 한 장의 후속 수정은 지정한 이미지에만 적용한다. 프롬프트 제공으로 제작을 대신하지 않는다.

**최초 생성부터 좋은 구성을 만드는 데 작업의 중심을 둔다.** 검수·탈락·반복 보정으로 품질을 확보하려고 시작하지 않는다. [최초 생성 명세](references/production-brief.md)로 현재 내용·카피에서 표현·편집·레이아웃을 먼저 구체화한다. 레퍼런스는 매력적인 포스터의 아이디어를 축적하는 용도이며 매 제작·제작자마다 웹 검색이나 원본 재열람을 필수 단계로 추가하지 않는다.

**제작을 마친 첫 완료 답변에 포스터 이미지와 각 원본 다운로드 링크를 보낸다.** 제작·파일 저장 뒤 [전달 준비 절차](references/delivery.md)를 실행하고, 그 절차에서 준비한 시안별 이미지·원본 링크·픽셀 크기 블록을 최종 답변에 그대로 전달한다. 준비된 답변 파일의 경로나 제작 완료 설명만 보내고 끝내지 않는다.

중앙 조정자가 전체 방향을 함께 설계하고 기본 다섯 제작자 에이전트가 한 장씩 맡는다. 현재 환경이 허용하는 만큼 동시에 실행하고 나머지 역할을 순서대로 실행한다. 사용자 지정 수량이면 그 수만큼 역할을 둔다. 실행하지 않은 동시성을 주장하지 않는다.

## 1. 내용과 조건 확정

자연어·메모·항목별 카피를 그대로 받는다. 표시 문구와 제작 지시를 구분하고 항목명·구분자를 인쇄하지 않는다. 제목만 있어도 제작하며, 텍스트 없는 요청도 존중한다. 글자를 요청했으나 표시할 문구가 전혀 없거나, 제작을 막는 누락·양립할 수 없는 조건이 있을 때만 짧게 확인한다. 선택 가능한 디자인 사항은 직접 결정한다.

전체 카피, 목적·대상·사용 매체, 수량·비율, 지정 스타일·색상·소재·배치·제외 요소와 사용자 자료의 역할을 정리한다. 따옴표나 필드 값의 철자·어절·문장부호·숫자·고유명사와 고정 줄바꿈을 보존한다. 문구 작성까지 맡긴 경우에만 새 카피를 쓴다. 주어지지 않은 행사 정보·슬로건·인용·로고·미세 문자를 만들지 않는다.

스킬·앱·도구의 호출명과 실제 표현 조건을 구분한다. "덕테이프 포스터로"는 이 스킬을 사용하라는 뜻이며 덕테이프 재질을 기본 조건으로 만들지 않는다. 사용자가 테이프·콜라주 등 재질을 별도로 지정하면 그 표현을 유지한다.

사용자 비율을 우선한다. 구도 유지를 요청한 참조 포스터는 별도 지시가 없으면 원본 비율을 따른다. 용도만 있으면 그 용도에 맞추고 아무 기준도 없으면 전부 세로 2:3으로 만든다. 여러 비율은 정해진 총수량 안에서 배분하며 스타일과 비율의 모든 조합으로 수량을 늘리지 않는다. 좁은 지정 스타일은 모든 방향의 공통 조건으로 유지한다.

## 2. 내용과 축적한 아이디어로 다섯 방향 설계

신규 제작·구도 재설계에서는 [아트디렉션](references/art-direction.md), [최초 생성 명세](references/production-brief.md)와 관련된 [디자인 아이디어](references/visual-research.md)를 사용한다. 현재 내용·대상·카피·매체에서 출발해 다섯 방향을 설계한다. 레퍼런스에서 축적할 것은 **왜 매력적인지에 대한 발상, 이미지 표현·편집·크롭, 색상·레이아웃·정보·글자·재질·정서의 아이디어**다. 매 요청마다 새 작품을 찾거나 다섯 제작자가 각각 원본을 다시 열 필요는 없다. 사용자가 특정 레퍼런스를 지정했거나, 현재 설계에 필요한 새로운 표현을 더 조사할 때만 해당 자료를 추가로 본다. 사용자 제공 이미지의 실제 열람과 보존은 별도 필수 조건이다.

축적한 아이디어는 현재 내용·언어·매체에 맞춰 새 관계로 설계하며, 특정 작품에 이번 결과를 대응시키거나 구도·장식을 복제하지 않는다. 특정 작가의 이름이나 "하이엔드"라는 형용사를 도구에 넣는 것으로 디자인을 대신하지 않는다. 작품마다 같은 모양·팔레트·스타일 목록을 반복하지 않는다.

중앙은 현재 내용에 맞는 다섯 스타일의 긍정적인 명세를 함께 설계한다. 이미지가 어떤 표현·편집으로 내용을 보여 주며 색·대비, 글자의 목소리, 재질·마감과 정서가 어떤 전체 인상을 만드는지 짧고 구체적으로 전달한다. [축적한 구성 문법](references/design-grammar.md)의 관계 아이디어는 필요할 때 선택적으로 참고하며 원본 작품 재열람을 의무로 만들지 않는다. 제작자는 배정된 스타일과 실제 카피에 맞는 좋은 읽기 구도를 자율적으로 구체화한다. 같은 읽기 순서·정렬·정보 묶음을 공유해도 스타일의 정체성이 뚜렷하면 독립된 방향이 될 수 있다. 고유한 다섯 레이아웃·첫 카피 역할·정보 순서·팔레트·서체 수량이나 고정 다섯 가족을 배정하지 않는다.

생성 전에 모든 방향을 함께 설계한다. 각 방향의 짧은 명세에 **현재 내용의 핵심 → 그것을 보여 주는 장면·행동·형태 → 전체 표현 체계 → 실제 카피의 기능과 타이포그래피 위계 → 구체적인 크롭·경계·정렬·읽는 흐름**을 연결한다. 실제 있는 문구를 eyebrow·Title·Subtitle·body copy·footer의 기능으로 정리하고 없는 역할이나 카피는 만들지 않는다. **일반 제목이 주어지면 즉시 Title로 인지되는 주된 타이포그래피 앵커로 설계한다.** 상대적 크기·무게·대비·여백으로 보조 문구·설명·안내와 분명히 구별하고, 다양성을 위해 제목을 작은 표식이나 먼 별도 구역으로 낮추지 않는다. 영어 병기·날짜·일반 초대·긴 본문이 역할 근거 없이 Title과 경쟁하지 않게 한다. 서체의 골격·폭·획 대비·무게와 한글·라틴·숫자의 기준선이 어울리는 체계를 선택하고 자세한 역할·서체 관계는 [최초 생성 명세](references/production-brief.md)에 따른다. Title의 명확한 인지와 본문·안내의 읽힘을 유지하면서 각 스타일의 정체성을 구현한다. 첫 시선이 항상 제목이어야 하거나 같은 위치·크기 비율·폰트·정보 순서를 쓸 필요는 없으며, 사용자 지정 역할·배치·순서와 무문자·제목만의 요청을 우선한다. 새 카피나 역할 수를 다양성의 의무로 만들지 않으며 내용과 무관한 대제목·중앙 오브젝트·하단 안내 틀을 자동 적용하지 않는다.

각 방향의 첫 시선, 다음에 읽을 유용한 정보, 주도하는 글자 역할과 이미지·글자의 경계를 명확히 정한다. 본문은 [읽는 흐름과 조판](references/production-brief.md#시선의-흐름-안에서-본문-조판)에 따라 실제 문장·기능별로 묶고, 이미지·제목에서 문단의 시작으로, 그 끝에서 실제 다음 안내 묶음의 시작으로 이어질 정렬·인접·방향·강약을 설계한다. 여러 구역이면 이미지의 크롭·열림과 그 사이의 전환 단서를 함께 정하며 한 열·패널·고정 순서를 강요하지 않는다. 빈 모서리마다 한 줄씩 흩어 놓지 않는다. 본문 서체의 한글·라틴·숫자 형태와 굵기, 문장 폭·줄바꿈·행간까지 최초 명세에서 선택하고 제목의 표현 효과와 구별한다. 큰 제목·강한 색·표현적인 그림도 전체 내용과 구성이 요구하면 적극 사용한다. 다섯 장을 작은 제목·중간 무게 글자·차분한 정보·따뜻한 바탕이라는 다른 반복으로 바꾸지 않는다. 특정 비중이나 조용함·강함의 수량을 고정하지 않는다.

실제 표시 크기에서 읽힐 본문 몸체·줄 폭·행간을 먼저 선택하고, 실제 문장이 필요한 면적을 이미지·제목과 함께 확보한다. 본문을 작은 캡션이나 남는 자리로 취급하지 않는다. 실제 날짜·시간·조건·URL도 의미 있는 단어 간격과 원문 기호를 구별하는 형태를 최초 조판 명세에 담는다. 그림·인쇄의 거친 질감을 작은 안내 글자에 씌우지 않고 정밀한 조판으로 구별한다. [표시 크기에서의 설계 예시](references/design-grammar.md#본문을-처음부터-읽게-만드는-면적과-글자)는 고정 글꼴·좌표·픽셀 문턱이 아니다.

**설명 문단과 실용 안내를 함께 담아야 하는 복잡한 카피라면**, 현재 사용 가능한 적합한 글꼴·렌더러로 [실제 카피의 구성 스케치](references/layout-guide.md)를 최초 네이티브 호출 전에 작성한다. 이번 내용에서 선택한 이미지의 시점·크롭·연결·큰 형태와 실제 글자 덩어리를 함께 그려 읽는 면적과 전체 관계를 설계한다. 무문자·Title만·간단한 카피와 실용 안내가 없는 Title+body에는 이를 의무로 늘리지 않는다. 단순 카피에서도 실제 글자 형태·면적과 이미지의 큰 표현을 함께 보이는 새 자기 저작 스케치가 명세를 구체화할 때만 선택적으로 사용한다. 명세만으로 충분하거나 사용 가능한 환경이 없으면 설치 없이 긍정적인 제작 명세로 바로 생성한다.

실제 출력 비율에서 카피 그룹과 이미지가 사용할 면적을 확인한다. 제목·일정·프레임이 비슷한 강도로 경쟁하거나 구조물 때문에 필수 안내가 좁은 칸에 몰리면 큰 덩어리의 관계부터 다시 설계한다. 작은 글자로 밀어 넣기 전에 프레임·큰 글자·이미지의 면적과 무게를 조정한다. 가로형과 세로형은 같은 틀을 늘이지 않고 각 비율의 읽는 흐름을 설계한다.

스타일의 차이는 실제 전체 이미지에서 판단한다. 같은 잘 읽히는 Title·body 순서와 정렬 구조를 재사용해도 이미지 표현·편집, 색·대비, 서체의 목소리·마감·정서가 설득력 있게 다른 체계를 만들면 독립 스타일이 될 수 있다. 색 필터나 글꼴 하나만 바꾼 변주를 완성된 스타일 설계로 대신하지 않되, 각 요소가 모두 서로 달라야 한다거나 레이아웃을 바꿔야 한다는 수량 조건은 두지 않는다. 사용자 지정 스타일·고정 구도·자산 보존 범위 안에서 가능한 차이를 설계한다. 실제 사용자 조건끼리 양립하지 않을 때만 기존 양립 불가 조건 확인 절차를 적용한다. 다섯 장 각각은 완성된 한 포스터이며 작품 안에 번호·스타일명·비교 설명을 넣지 않는다.

**기본 출력에서 [단색 바탕과 고딕 블록 중심 템플릿 구성](references/art-direction.md#기본-스타일-제외)을 제외한다.** 같은 정보 판형을 작은 그림·글꼴·질감이나 빈 실내 면으로 꾸미지 않는다. 현재 내용에서 선택한 이미지 표현·편집·공간과 글자의 긍정적 관계를 제작 명세의 중심으로 삼는다. 고딕·여백·사진 자체의 금지와 혼동하지 않으며, 현재 적용되는 명시적 전체 구성 지시는 해당 범위에서 우선한다. 구체적인 정의와 예외는 연결된 아트디렉션을 조사·제작·선택에 동일하게 적용한다.

사용자가 글자만의 구성이나 비문자 요소 제외를 명시하지 않은 경우에는 내용의 핵심을 맡는 실질적인 비문자 시각 요소를 설계한다. 글자·여백만의 출력이나 작은 아이콘·희미한 질감으로 이 조건을 우회하지 않는다. **비문자 요소를 반드시 거대한 단일 오브젝트로 만들 필요는 없다.** 장면의 관계, 반복되는 행동, 이미지의 경계·연속성, 읽을 수 있는 구조도 발상을 맡을 수 있다. 사용자가 글자만으로 구성하거나 비문자 요소를 제외하라고 명시하면 그 조건을 우선하고 타이포그래피·레이아웃으로 내용을 설계한다.

스타일이 열린 요청에서는 **둥근 클레이 글자 + 강한 보색 + 장난감 같은 덩어리**, **큰 오브젝트 + 큰 제목 + 작은 하단 정보**, 내용 없는 크롬·홀로그램·매끈한 블롭 등 익숙한 생성 패키지의 우선순위를 낮춘다. 한 요소를 쓰는 것 자체가 결함은 아니다. 사용자 지정 표현은 유지하면서 내용에 맞는 관계와 마감을 설계한다. 대신 모든 결과를 무채색·종이 질감·미니멀리즘으로 획일화하지 않는다.

## 3. 제작자별 독립 생성

협업 도구가 있으면 [병렬 제작](references/parallel-production.md)을 따라 방향당 한 제작자를 배정한다. 각 제작자는 원문 전체, 확정 카피와 조건, 자신이 맡은 전체 시각 방향, 가까운 방향과의 구분, 필요한 사용자 자료를 받는다. 협업 도구가 없으면 같은 수량·방향·검수 기준으로 직접 제작하고 에이전트를 실행했다고 말하지 않는다. 생성 직전 방향을 짧게 알리고 별도 선택·승인 없이 요청한 장수를 제작한다.

Codex 내장 `image_gen`을 실제로 호출하고 현재 도구 스키마를 따른다. API 키·SDK·이미지 CLI를 기본 흐름에 넣거나 지원하지 않는 인자를 만들지 않는다. 각 호출은 문구와 디자인을 포함한 **단일 평면 포스터 한 장**을 만든다. 다섯 패널·콘택트시트·액자·공간 목업으로 합치지 않는다. 먼저 만든 시안을 다른 방향의 신규 참조로 자동 이월하지 않는다.

제작자가 가진 전체 요청·검수 자료와 이미지 도구의 제작 명세를 구분한다. **최초 명세는 구현할 이미지 표현 → 실제 카피 한 벌의 조판 형태 → 장면·구도·색·마감과 필수 조건**이 이어지는 짧은 긍정적인 명세로 쓴다. 형태·경계·세부·빛을 어떻게 만드는지 먼저 정해 그 규칙으로 장면·재료의 묘사를 선택·생략·변형하고, 실제 있는 문구의 역할·위계·읽는 면적과 카피를 한 번 전달한다. 사용자가 줄바꿈을 고정하지 않았다면 원래 어절 경계의 공백을 선택한 의미 단위의 soft 줄바꿈으로 조판해 그 카피 한 벌에 담는다. 그 외의 철자·어절·숫자·기호·공백과 고정 줄바꿈은 보존하며 역할 설명·항목 표시는 새 인쇄 문구로 추가하지 않는다. 같은 카피를 원문 전체나 별도 그룹 JSON으로 다시 붙이지 않는다. 필요한 사용자 조건·참조 역할·선택한 전체 시각 관계·마감·출력 조건을 전달하고 평가표·레퍼런스 해설로 설계를 대신하지 않는다. 간결함 때문에 문구나 중요한 대상·행동·참조 보존 조건을 생략하지 않는다. 자세한 최초 전달은 [제작 명세](references/production-brief.md#이미지-도구에-전달할-내용)를 따른다. 국소 수정은 실제 대상 이미지를 참조하고 바꿀 부분과 유지할 관계를 중심으로 지시한다.

모든 최초 생성과 수정 명세에 현재 적용되는 기본 스타일 제외 또는 해당 이미지에 한정된 명시적 사용자 해제를 함께 전달한다. 협업 없는 직접 제작에도 동일하게 적용하며, 제외 문장만 쓰지 말고 선택한 이미지·공간·글자의 긍정적 관계도 구체적으로 지시한다.

생성·수정마다 "요청한 화면 비율을 유지하면서 현재 도구와 모델이 지원하는 가능한 최대 해상도로 출력"하도록 명시한다. 사용자의 특정 픽셀 크기·낮은 해상도 요청을 우선한다. 설정이 있으면 지원 최대 설정을 쓰고, 설정이 없으면 프롬프트 요구가 실제 최대 크기를 보장하지는 않는다고 판단한다. 리사이즈를 원본 생성 해상도나 새 세부 묘사로 취급하지 않으며 최대 크기를 확인하려고 반복 생성하지 않는다.

사용자 이미지의 실제 픽셀을 먼저 보고 수정 대상·구도 참고·스타일 참고·실제 대상 재현을 구분해 필수 자료를 각 호출에 전달한다. 로컬 경로 또는 현재 도구의 대화 이미지 참조를 정확히 사용한다. 모든 필수 이미지를 전달할 수 없으면 누락된 자료를 확인한다. 구도·위치·비례 보존을 요청한 자료는 주된 대상과 카피 블록의 경계·상대적 위치·크롭을 먼저 확인하고, 반환 결과를 같은 기준으로 비교한다. 형태가 닮았다는 이유로 위치·크기 보존까지 통과시키지 않는다. 별도 비율 변환을 요청했다면 필요한 변환과 유지할 관계를 구분한다. 원본 화면·로고를 확보하지 못한 모사를 정확한 재현으로 전달하지 않는다. 조사용 작품을 사용자 자산인 것처럼 쓰거나 원작의 카피·로고·특정 구도를 그대로 이식하지 않는다.

## 4. 이미지와 전체 세트 검수

실제 결과와 사용 크기에서 전체 카피·조건·비율·판독과 명백한 구조·합성 결함을 확인한다. 전체 인상과 다섯 방향의 차이를 보고, 한글·간격·경계·재질이 애매하거나 결함이 보이면 원본에서 해당 부분을 확인한다. 일반 제작에 일곱 항목 점수표나 반복적인 세부 검사 기록을 추가하지 않는다. 사용 크기를 모르면 확인한 표시 범위를 남기며 인쇄 적합성을 단정하지 않는다.

각 항목이 따로 읽히거나 재질이 정교하다는 이유로 전체 관계까지 통과시키지 않는다. [아트디렉션](references/art-direction.md)의 방법으로 실제 첫·다음 앵커, 필요한 카피 전체를 찾는 경로, 해당되는 대상·행동·결과의 대응을 확인한다.

아트디렉션의 일곱 기준은 설계와 실제 실패의 원인을 이해하는 데 쓴다. 일반 제작에서는 문구·조건·판독과 보이는 결함에 집중하고 좋은 결과를 검수 항목에 맞추려고 다시 만들지 않는다. 내용이 바뀌어도 그대로 쓸 범용 발상, 반복되는 대제목·오브젝트 구도, 붙여 놓은 글자, 임의 장식, 가짜 작은 문자, 불균일한 한글, 어긋난 빛·접촉·재질은 AI 슬롭의 구체적 원인이다. 제작 주체를 판별했다고 주장하지 않는다.

다섯 장을 나란히 보고 가장 약한 시안까지 같은 기준으로 확인한다. 실질적으로 다른 스타일의 정체성과 잘 읽히는 구도가 구현됐는지, 현재 내용의 큰 관계와 세부 조판·이미지 마감이 함께 해결됐는지 확인한다. 주제를 설명하는 문장이나 매끈한 표면만으로 완성도를 인정하지 않는다. 강한 표현·거친 마감도 내용과 일관된 의도가 있으면 유지한다.

해당 이미지에 기본 스타일 제외가 적용되면 실제 축소·사용 크기에서 [동일한 제외 구성](references/art-direction.md#기본-스타일-제외)을 대조한다. 작은 비문자 요소가 있거나 카피·정렬이 정확해도 위반을 통과시키지 않는다. 이 경우 폰트·배경색·질감만 교체하지 않고 남은 보정 한도 안에서 이미지의 표현·면적·크롭과 글자·정보의 공간 관계를 함께 다시 설계한다. 이전 결과를 유지하는 선택에도 현재 적용되는 제외를 확인한다. 한도 뒤에도 남으면 해당 결과를 완성 시안·추천 후보·최종 선택본에 넣지 않고, 요청 수량의 미해결 역할로 기록해 알린다. 원본과 이력은 보존하되 적합한 결과인 것처럼 전달하지 않는다.

이 대조에는 이미지·장면·편집이 실제 전체 구성을 조직하는 관계와 제목·안내 판형에 부가물을 붙인 관계가 남는지를 기존 검수 기록에 짧게 남긴다. 명시적 이미지 제외 요청이면 글자·공간의 관계를 본다. 이미지의 존재·면적·재료명만으로 해소를 인정하지 않으며 읽히는 정보 묶음이나 단색 여백 자체를 위반 근거로 삼지 않는다.

보정 전에 실제 보기의 실패 위치, 사용자 조건의 근거 또는 깨진 목적·판독·관계·마감, 확인할 변화와 보존할 장점을 짧게 정한다. 계획의 좌표·글자 크기·줄 수·무늬 수와 다르다는 사실만으로 결함을 만들지 않는다. 카피·사용자 조건과 필요한 대응·읽는 흐름·방향의 구분이 작동하면 계획을 맞추기 위한 호출은 생략한다. **이미지당 최초 생성 뒤 재생성을 포함한 자동 보정은 최대 두 번**이며 채울 의무는 없다. 중앙과 제작자 호출을 합산하고 실패한 시도도 센다. 국소 결함은 대상 이미지를 수정하고 발상·구성의 실패는 관계부터 재설계한다. 매번 전체 카피·조건을 재확인하고 같은 보기에서 전후를 직접 비교한다. 필수 조건을 먼저 대조한 뒤 실제로 해결된 실패와 새 퇴행을 함께 비교해 선택한다. 계획 일치만 늘고 이미 작동하던 관계·판독·마감이 나빠졌으면 이전의 적합한 결과를 유지한다. 관찰한 실익이 동등하거나 불확실해도 이전의 적합한 결과를 우선하며 최신 파일을 자동 채택하지 않는다. 문구 삭제·효과 추가로 결함을 가리지 않고, 한도 안에서 남은 결함과 선택 이유를 알린다.

후속 변경은 지정한 이미지와 부분에만 적용하며 다른 문구·구도·빛·질감을 원본과 비교한다. 한 장의 수정 요청을 새 다섯 장 제작으로 확장하지 않는다. 대상이나 범위가 불명확할 때만 확인하고, 비의도 변화가 남으면 "나머지 그대로"라고 단정하지 않는다.

## 5. 파일과 전달

실제 반환 파일의 너비·높이를 확인한다. 사용자 경로 또는 프로젝트 산출물 폴더에 원본을 보존하고 충돌 없는 이름으로 방향별 적합한 최종 파일을 개별 저장한다. 최종 선택이 없는 역할의 원본은 시도 이력으로 보존하며 완성본으로 재명명하지 않는다. 보정본을 새 스타일로 세지 않으며 요청 수량과 최종 파일 대응을 확인한다.

중앙은 각 제작자의 선택 결과를 [전달 레코드](references/delivery.md#제작자와-중앙의-전달-레코드)로 모으고, 실제 선택 원본과 현재 사용자 대화에서 쓸 표시·다운로드 참조를 확보한다. 참조가 빠진 역할은 파일 전달을 해결하며 이미지의 재생성으로 대신하지 않는다. 하위 에이전트의 이미지 카드나 캐시 경로가 사용자에게 자동 전달됐다고 가정하지 않는다.

코드 실행 환경에서는 [답변 준비 도구](scripts/prepare_delivery.py)로 이미지·원본 링크·실제 픽셀 크기가 한 묶음인 `response.md`를 만든다. 선택본의 참조 누락이나 로컬 다운로드 파일과 선택 원본의 바이트 불일치를 준비 도구가 기록한다. 대화·네이티브 참조는 실제 선택 원본을 첨부해서 확보하며 도구가 그 파일 동일성을 인증하지 않는다. 전체 상태와 해당 역할을 확인하고 현재 파일 전달 수단으로 해결한 뒤 다시 준비한다. 도구는 원격 참조의 접근성이나 실제 화면 표시를 인증하지 않는다. 코드 실행 환경이 없거나 실제 첨부를 문자열 준비 도구로 표현할 수 없으면 같은 전달 레코드로 각 블록을 직접 구성한다.

**최종 답변에는 준비한 모든 시안 블록의 본문을 그대로 보낸다.** 각 적합한 선택본의 이미지를 개별 표시하고 바로 아래에 그 선택본의 원본 해상도 파일 링크와 픽셀 크기를 둔다. 실제 이미지 첨부·미디어 블록 또는 Markdown 이미지와 파일 링크를 쓰며 코드 블록으로 감싸지 않는다. 이미지 밖의 설명은 짧게 덧붙인다. 이미지 표시를 파일명·경로·갤러리 링크로 요약하거나 이미지·원본 링크를 다음 답변으로 미루지 않는다. 기본 다섯 역할 중 적합한 선택본만 완성 시안으로 전달하고 미해결 역할은 별도로 알린다. 각 요청 역할마다 현재 적용되는 필수 조건과 기본 스타일 제외를 충족한 시도의 경로를 선택한다. 적합한 시도가 없으면 최종 선택 없음(NONE)과 미해결 사유를 기록한다. 제외·실패·미선택 시도는 원본과 이력에 보존하고, NONE인 역할도 요청 수량과 미해결 분모에 남긴다. 적합한 이전 결과를 유지할 수 있으며 보정본을 새 역할로 세거나 한도를 초기화해 수량을 채우지 않는다. 이미지 밖의 방향 설명과 남은 문제만 짧게 적고 내부 프롬프트·설정·진단표를 붙이지 않는다. 최대 설정 적용을 확인했을 때만 최대 해상도라고 알린다. 도구가 없거나 실패하면 실제 상태를 알리고 생성하지 않은 파일·에이전트·검증을 완료로 세지 않는다.

스킬 개선·비교·다중 에이전트 평가 요청에서는 [평가 루프](references/evaluation-loop.md)를 적용한다. 일반 포스터 제작에는 외부 평가자를 기본 단계로 추가하지 않는다.
