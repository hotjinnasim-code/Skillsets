# 선택본을 사용자에게 전달하기

제작을 마친 첫 완료 답변의 산출물은 **개별 포스터 이미지 + 해당 선택본의 원본 다운로드 링크 + 원본 픽셀 크기**다. 이미지 생성·파일 저장·하위 에이전트의 이미지 카드만으로 전달이 끝난 것으로 처리하지 않는다. 아래 절차는 제작한 결과를 전달하기 위한 것이며 이미지 재생성이나 추가 디자인 평가를 요구하지 않는다.

## 제작자와 중앙의 전달 레코드

제작자는 배정된 역할마다 다음 필드를 한 묶음으로 반환한다. 중앙은 요청한 역할 수만큼 레코드를 모은다. 수정 요청 한 장에는 한 레코드만 필요하다.

| 필드 | 의미 |
| --- | --- |
| `id`, `label` | 고유 역할 식별자와 짧은 스타일 이름 |
| `selection` | `selected` 또는 `none` |
| `original_path` | 선택한 최종 원본의 실제 절대 경로. 대화 참조만 이용할 때는 생략 가능 |
| `display_ref` | 현재 사용자 대화에서 이미지를 표시하는 실제 문자열 참조 |
| `download_ref` | 그 선택본의 원본 해상도 파일을 다운로드하는 실제 문자열 참조 |
| `width`, `height` | 선택 원본의 실제 픽셀 크기. 로컬 파일을 읽을 수 있으면 도구가 확인 |
| `reason` | `none`일 때 적합한 선택본이 없는 사유 |

아직 확보하지 못한 표시·다운로드 참조는 생략하거나 `null`로 둔다. 누락은 중앙이 해결할 전달 문제이며, 적합한 원본이 없는 `none`과 구분한다. `none` 레코드에는 이미지 필드를 넣지 않는다. 내부 제작·선택 이력은 기존 절차대로 보존하고 최종 답변에 붙이지 않는다.

## 현재 대화에서 쓸 파일 참조 확보

중앙은 선택본의 실제 파일과 현재 대화에 쓸 참조를 확보한다. 제작자의 비공개 캐시 경로나 이미지 카드가 사용자에게 자동 전달됐다고 가정하지 않는다. 필요하면 현재 환경의 실제 파일 보존·첨부 수단으로 **선택 원본**을 사용자 대화에 넘기고, 반환된 표시 참조와 원본 파일 참조를 레코드에 기록한다. 미리보기는 화면 표시용으로 쓸 수 있지만 원본 다운로드는 축소본·이전 시도로 대체하지 않는다.

- `local`: 현재 대화가 절대 로컬 이미지·파일 경로를 지원할 때만 쓴다. 실제 읽을 수 있는 `original_path`가 필수다. 표시·다운로드 필드를 생략하면 그 원본 경로를 사용한다. 명시한 `null`은 아직 확보하지 못한 참조다.
- `dialog`: GPT Work 등에서 현재 대화의 파일·미디어 참조를 쓸 때 선택한다. 도구나 첨부 기능이 실제로 제공한 `display_ref`와 `download_ref`를 모두 명시한다. 문자열 준비 도구는 URL 스킴이 있는 Markdown 대상만 다룬다. 불투명한 식별자·미디어 객체는 아래 직접 전달 절차를 쓴다. 로컬 경로에서 대화 URL을 추정하거나 특정 URL 형식을 만들어내지 않는다. 로컬 원본을 읽을 수 없으면 실제 반환 정보에서 확인한 `width`와 `height`를 넣고 확인 범위를 `delivery.json`에 기록한다.

사용할 파일 전달 기능이 없으면 그 한계를 해당 역할에 알린다. 링크 누락을 해결하려고 포스터를 새로 생성하거나 외부 호스트에 업로드하지 않는다. 전달 수단이 있으면 누락된 원본만 다시 첨부하거나 참조를 다시 확보한다.

## 답변 본문 준비

코드 실행 환경에서는 `requested_count`, `reference_mode`, `items`를 담은 JSON 파일로 [prepare_delivery.py](../scripts/prepare_delivery.py)를 실행한다. 경로는 현재 프로젝트 안에 정하고 출력 디렉토리는 새 이름을 쓴다. 아래의 `SKILL_DIR`, `MANIFEST`, `NEW_OUTPUT_DIR`는 실제 경로로 바꾸는 예시 인자다.

```sh
python3 SKILL_DIR/scripts/prepare_delivery.py MANIFEST.json --output-dir NEW_OUTPUT_DIR
```

`requested_count`는 양의 정수이고 `items`는 그 수와 정확히 일치하는 전달 레코드 배열이다. `reference_mode`는 `local` 또는 `dialog`다. 중복 역할, 잘못된 필드 형식, 안전하지 않은 참조는 입력 오류이며 종료 코드 1로 중단한다. 기존 출력은 덮어쓰지 않는다. 새 패키지 설치·API 키는 필요하지 않다.

도구는 `response.md`와 `delivery.json`을 만들고 답변 본문을 출력한다. 읽을 수 있는 PNG·JPEG·정적 WebP 원본의 컨테이너 구조·헤더 크기·SHA-256을 확인하고, 로컬 다운로드 파일이 선택 원본과 같은 바이트인지 확인한다. 전체 픽셀 디코딩, 원격 참조의 접근성, 실제 대화의 이미지 표시·다운로드 성공을 인증하지 않는다.

| 상태 | 다음 행동 |
| --- | --- |
| `READY` / 종료 0 | 모든 선택본의 답변 블록이 준비됐다. 본문을 사용자에게 전달한다. |
| `PARTIAL` / 종료 0 | 적합한 선택본과 `none` 사유를 함께 전달한다. 미완성 역할을 완성 수량으로 세지 않는다. |
| `NOT_READY` / 종료 2 | 선택본의 파일·참조·크기에 문제가 있다. 해당 전달 문제를 해결하고 새 출력 디렉토리로 다시 준비한다. 해결 불가한 역할은 미해결로 알린다. |

코드 실행이 불가능하거나 실제 첨부가 네이티브 미디어 블록·불투명한 식별자 등 문자열 준비 도구로 표현할 수 없는 참조를 사용하면 같은 레코드로 답변 블록을 직접 구성한다. 실제 미디어 블록으로 이미지를 표시하고 바로 아래에 실제 원본 첨부·다운로드 링크와 크기를 둔다. 불투명한 도구 객체를 문자열 URL로 직렬화하지 않는다. 문자열 준비 도구의 사용 여부가 전달을 막는 조건이 되어서는 안 된다.

## 최종 답변에 보내기

**준비한 모든 시안 블록의 본문을 최종 답변에 그대로 보낸다.** 네이티브 미디어를 쓰는 경우에도 시안별 이미지와 원본 링크의 짝을 유지한다. `response.md` 파일 링크, 제작 완료 설명, 갤러리 링크만 보내거나 본문을 코드 블록으로 감싸지 않는다. 이미지와 원본 링크를 다음 답변으로 미루지 않는다. 짧은 스타일 설명은 이미지 블록 밖에 덧붙일 수 있다.

`READY`는 답변이 준비됐다는 뜻이다. 도구 실행만으로 사용자에게 표시됐다고 주장하지 않는다. 사용자에게 표시·다운로드 문제를 보고받으면 기존 선택 원본의 실제 첨부와 참조부터 복구한다.
