## Five independent whole styles

M requires differences in whole systems: concept, scene organization, crop, type roles, spatial structure, and information flow. Its comparison removes color/material/effect labels and then asks whether the actual content justifies the structure. It prohibits both the familiar large-title/central-object/footer repetition and replacement by five uniformly quiet layouts. Each maker receives one direction and the complete copy, cannot add recursive makers, and cannot read another maker's generated image or prompt. A prior result must not be carried into another new direction as an image reference. No unrequested campaign palette, font, or layout is imposed. (S:28–44; A:40–55; P:7–21.)

Independence here means separate production and no peer-output borrowing. It does not mean five isolated designers: the coordinator intentionally shares the source brief and jointly designs the set. That shared planning is compatible with diversity only if each whole direction remains structurally different.

The pins contain five role IDs, not five direction specifications or output artifacts. Planned roles therefore cannot establish completed style differences. Before production, the short direction records and closest-neighbor comparisons must exist. After repair and selection, the coordinator must compare the actual complete set again; independently choosing an attractive file for each role can still leave two convergent styles. P:29 and E:23 supply the needed final-set check. No image judgment is possible in this audit.

## Bounded repair and preservation during selection

The accounting is internally aligned: one initial native attempt plus at most two automatic corrections for each image, including regeneration, failed attempts, and coordinator calls. J assigns three native attempts and two corrections to each of five roles, with an aggregate ceiling of 15. These are ceilings, not targets. Unused attempts in one role do not authorize a fourth attempt in another, and renaming a version or rerunning unchanged instructions does not reset the limit. (S:62; P:21, 29; E:74; J:87–127, 135–136.)

The repair trigger is an observed failure of mandatory conditions, purpose, readability, relationships, or finish. The instruction first identifies its location, intended improvement, and strengths to preserve. A local defect is edited against the actual target image; a composition or concept failure can require redesign within the same constraints. Every attempt rechecks the full copy and conditions and compares thumbnail, usage, and original views. Selection considers solved failures and new regressions together. A prior suitable result wins when improvement is equal or uncertain; neither the latest file nor a smoother surface automatically wins. Deliberate roughness, asymmetry, distributed information, and internal crops retain protection when they remain functional. (S:46, 54–64; A:77–79.)

“Prior suitable” is important: an attractive earlier file with missing copy or a mandatory violation cannot gain compliance through this preference. If no suitable result survives the cap, retain the artifacts and report the unresolved failure or unassessable condition. A selection across different versions must be labeled a selection, not proof that one version's entire performance improved. The text requires all five roles to remain accounted for and prevents counting a correction as a new style. Successful preservation, however, needs actual paired observations and call records, none of which is in these pins. (S:68–70; P:25–31; E:72–82.)

## Native-tool and copy boundary

The native route is explicit: call the built-in `image_gen` under its current supported schema to create one flat poster containing both image and copy. The maker's full source context is separated from the native production prompt. The tool gets one printing-copy set, essential conditions, relevant asset roles, concrete image/type/spatial relationships, and output requirements. It must not receive the same copy again in raw request, JSON, evaluation tables, and reference commentary. Prompt brevity cannot drop important content. Local repair references the actual target and states both the change and preserved relationships. (S:44–50; P:17–21; E:15.)

With no client assets in this case, another maker's result or a research poster must not become an implicit new-generation reference. Native call records are needed to verify that isolation. Reference research informs design principles; it does not authorize copying a source poster's copy, logo, or specific composition. (S:44, 50; R:20, 44; J:91–125, 129.)

No pinned tool schema or call payload demonstrates the actual binding, ratio support, output path, or returned metadata. “Maximum supported resolution” in a prompt is not proof of a maximum setting; M expressly recognizes this. Actual returned dimensions must be measured. Local saving/copying, inspection renders, and view resizing are distinct from native image generation. They cannot establish native text accuracy, added detail, or higher native resolution. A text overlay or alternate renderer is not specified by this production route and would need to be disclosed as a workflow deviation. (S:48, 68–70.)

## Actual concurrency

J schedules five logical makers but caps worker concurrency at three. P:13 requires remaining roles to use freed slots and forbids bypasses through other chats or execution channels. A compatible schedule is at most three active makers, then remaining makers as slots become available; five simultaneous makers would exceed this case's cap even if another environment allowed five. Available platform capacity must also account for a resident coordinator when the platform's slot limit includes it. (S:10, 42; P:3, 11–13; J:87–127, 138.)

The plan proves neither that three makers actually overlapped nor that native image operations overlapped. Worker/session overlap and native-call overlap are separate quantities: a provider may serialize native work while agents are active. Role IDs and a concurrency ceiling are not observations of either. Record maker and critic start/end intervals, native invocation/completion intervals, actual peak worker occupancy, and any serialization or failed calls. Apply the lower of the case cap and available capacity, including concurrently active critic workers if present. The complete-set review prerequisite naturally permits separate maker and critic phases. (E:19, 23–25.)

This audit ran no production workers and made no native calls. Actual production concurrency is therefore unmeasured. The only defensible pinned description is **five planned maker roles, worker cap three, and a declared zero generated images**, not five-agent simultaneous execution or demonstrated concurrent native generation.

The next runtime record would need to close this complete five-poster case within its existing limits, preserve every role and attempted correction, resolve the pre-execution ambiguities above, and distinguish declared procedure from observed tool events and image inspection. These pins support that bounded workflow specification; they do not establish its executed result or reliability on other requests.
