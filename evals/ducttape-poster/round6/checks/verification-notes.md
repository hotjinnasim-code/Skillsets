# 증거 검수와 도구 보완

최종 이미지 판정은 **PASS 1장 / FAIL 14장 / NOT_ASSESSABLE 5장**이다. 이 문서는 파일·기록 검증과 검수 도구의 보완을 설명하며, 시각 평가 점수나 선택을 바꾸지 않는다.

## 서로 다른 결과

- 파일 바이트와 실제 연결·집계: 독립 기술 검수에서 PASS. 원본 경로 1,125개, 고유 파일 902개, 생성 호출 47개와 최초·최종 선택 40행, 평가 기록 120개·점수 값 840개가 일치했다.
- 평가 절차의 정합성: FAIL. 긴 한영 안내의 공백 전사와 일치 표기가 충돌해 해당 사례의 다섯 장은 NOT_ASSESSABLE이다. 원래 비교 기준과 원시 기록을 유지한다.
- 원래 검수 도구: [독립 기술 검토](final-technical-review/report.md)는 **FAIL**이다. 실제 자료는 올바르지만, 모의 자료의 잘못된 관찰 식별자·완료 세션·집계·통과 표기를 거부하지 못했다.
- 별도 보완 검사: [최종 수정본 결과](validator-repair-v2/regression-report.md)는 **PASS**이다. 기존 13개·추가 11개·동료 검수 후 추가 8개로 총 32개 검사의 기대 결과가 모두 확인됐으며, 실제 아카이브의 판정과 원점수는 그대로다. 이 결과는 독립 기술 검토의 FAIL 보고서를 대체하지 않는다.

보완한 검사는 관찰의 역할·사례·익명 이미지·평가자 연결, 완료 세션과 추적 기록의 일치, 완료 사건, 실제 기록·점수 총계와 이미지·사례별 판정을 확인한다. 판정 불가 자료를 보존하는 모드에서도 잘못된 연결이나 부당한 통과 표기를 거부한다. 최초 보완본의 동료 검수에서 발견한 요약 경로 은폐와 전체 판정 분포 대조 누락도 최종 수정본에서 차단했다. [첫 동료 검수](peer-review-v1.json)와 [두 항목의 보완 수락](peer-review-v2.json), 기존 수정본을 함께 보존한다. 모의 검사는 파일 해시 검증 이후 메모리에 주입한 제어 흐름 검사이며, 다른 바이트의 아카이브를 새로 만든 검사가 아니다.

`raw/audit_portable_archive.py`는 당시 실행한 코드의 정확한 스냅샷으로 보존한다. 보완한 검사기는 다음 명령으로 현재 아카이브를 읽을 수 있다.

```sh
python3 evals/ducttape-poster/round6/checks/validator-repair-v2/audit_portable_archive.py evals/ducttape-poster/round6
```

## 보존과 범위

독립 기술 검토의 입력·출력·추적 기록과 수정 전 보고서 입력을 보존했다. 이후 보고서 첫 문단의 두 표현을 명확하게 고치고 마지막 빈 줄을 정리했다. 변경은 [편집 변경 기록](post-review-editorial-changes.json)에 있다. 원시 평가와 이미지는 수정하지 않았다. 별도 보완 검사 수행 중 기존 아카이브 938개 파일도 전후 해시가 일치했다. 이후 추가한 검사 자료는 원본 매핑 인덱스와 구분해 저장한다.

원시 보고서의 Markdown 줄바꿈 공백과 마지막 빈 줄은 원본 해시를 지키기 위해 보존한다. 전체 Git 공백 검사의 이러한 경고를 숨기거나 원시 파일을 고치지 않는다.

일반적인 최초 생성 실패의 봉인 경로는 여전히 지원되지 않는다고 공개한다. 이번 실행에서는 최초본 20개가 모두 반환됐고 실패 호출은 없으므로 그 분기는 실행되지 않았다. 부분 자료·다른 호출 수의 모든 일반 경로를 검증한 것으로 해석하지 않는다. 세션과 해시는 실제 의미적 이미지 열람, 외부 이력의 진위, 인간 제작 여부나 미래의 하이엔드 품질을 인증하지 않는다.
