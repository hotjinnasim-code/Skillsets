# X closure recording amendment

The original prospective scope review and its X-OPS-01 finding remain unchanged in `history/x-publication-prep`. This amendment changes only the two unexecuted closure scripts. Exact before/after code copies and SHA-256 pins preserve the versions. No actual R21 closure, evaluation, native generation, or fictitious scoring fixture was run or created.

`close_r21_makers.py` verifies its frozen runtime/helper pins before importing the unchanged copied `method-recording-v2/prepare_reviews_compact.py`. It calls that helper's existing `terminal()` validator, retaining the same actual stage inventory, one initial plus at most two repairs, and exclusive selection-or-unavailable contract. The existing validator accepts unavailable only after all three actual attempts failed with no returned image. The maker record now preserves the actual terminal/outcome/counts and explicit null selection/selected stage for unavailable roles. Existing maker completion and unique-session requirements remain. No helper, attempt bound, raw evidence, client reference, or native selection is changed.

`close_r21.py` verifies those terminal pins and uses the actual readiness in each wave. Initial or selected UNREADY preserves its exact readiness errors, five NA members, zero new critics/processes/sessions/scores, zero observed score slots, and the unchanged expected 105 slots/three critics. It cannot silently discard an existing completion or reuse/summary file as UNREADY. A failed initial followed by a returned repair can therefore preserve an initial UNREADY while allowing the existing preparer's separate fresh selected whole-five evaluation. An all-failed role remains unavailable and any unready complete-set wave remains NA. No additional critic is launched to rescue either branch.

Fresh/reused critic completion is recorded as a process lifecycle rather than forced to exit zero. The unchanged `summarize.py` already marks nonzero exit, input-pin, completion/session, missing raw, and trace errors as procedure NA. Closure preserves those original gates/counts and the completion's actual exit/input-pin values, original and actual trace pins, reported IDs, actual `thread.started` IDs, and error events. Missing diversity stays null/unavailable rather than becoming a fabricated score. The count of completed fresh CLI processes is derived from actual completion records (0, 3, or 6 across the waves); trace-backed session counts are separate and may be smaller when a process failed before a thread started. Duplicate/missing session observations stay recorded and are judged by the original summary rather than being replaced. A completion file with a recorded process exit and completion timestamp is required; this change does not label a missing or still-running process as closed. Reuse retains the original existing whole-context binding audit and introduces zero new processes/sessions/scores.

The generated report now conditionally describes assigned evaluation and actual fresh/reuse/UNREADY process/session counts. It does not claim that unexecuted views were inspected or that all requested images returned. Its initial link points to readiness when no initial summary exists. Native returned/failed/repair counts and unavailable counts come from the original validated terminal inventory; fresh raw score/gate counts still come verbatim from the original summary. The fixed seven dimensions, every score >=4 for each of three critics, diversity >=4 for each critic, and mandatory conditions are unchanged.

Verification was limited to `ast.parse` syntax checks for the two final scripts, manual diff/control-flow/schema comparison against the frozen terminal/preparer/summary code, exact before/after copies, unchanged original audit hashes, and unchanged frozen helper bytes. No scripts/helpers were imported or executed by this verification, no tests or sample score records were generated, and no native image or actual result was assessed. This resolves the static lifecycle mismatch in the amended code; runtime behavior and quality remain unverified. Packaging source-list updates, if wanted, remain ROOT's separate follow-up.
