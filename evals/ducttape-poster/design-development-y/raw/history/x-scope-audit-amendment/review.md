# X 조건부 경계 수정의 독립 재확인

현재 `drafts/candidate-x`의 변경 문서 두 개, W 대비 전체 차이, `history/x-draft-amendment/`의 세 기록을 확인했다. 최초 감사는 수정하지 않고 이 기록을 별도로 작성한다. 현재 범위 감사 상태는 `scope_audit_complete_no_unresolved_issues`이며 미해결 항목은 없다. 이는 문서 범위의 판단으로 이미지 품질 통과가 아니다.

최초 감사의 `X-SCOPE-01`은 해결됐다. `production-brief.md:21`과 `parallel-production.md:15`의 새 문구가 각각 “사진 경계”에서 “비문자 이미지가 있을 때의 경계”로 바뀌었다. 사진을 전제하지 않고 실제 비문자 이미지가 있을 때만 그 경계와의 관계를 설계한다. 이미지 없는 요청에는 안내의 면적·정렬축·다음 묶음의 시작이 남으므로 사용자 이미지 제외 조건과 양립한다.

각 파일의 변경은 해당 구절 한 번뿐이다. 현재 파일의 구절을 되돌리면 최초 X 파일의 SHA-256과 바이트 길이가 정확히 복원되고, 현재 파일 SHA도 amendment 기록과 일치한다. 나머지 10파일은 최초 X 및 라이브 W와 바이트가 같다. 현재 X/W는 각각 12파일이며 추가·삭제 없이 처음부터 수정했던 두 제작 문서만 다르다. 최초 X 기록 세 개와 최초 감사 두 개도 유지돼 있다.

목적 식별·본문에서 안내로의 연결·다섯 전체 관계의 차이를 강화한 원래 X 범위는 그대로다. 고정 제목 우선·단일 진입점/레이아웃·공통 폰트/격자·새 점수/픽셀 하한·추가 평가/보정·원작 재탐색 요구는 추가되지 않았다. 사용자 지정 카피·스타일·배치·순서·자료 보존의 우선순위, 조건부 구성 스케치와 미지원 환경의 명세 fallback, 기존 네이티브 생성 및 코드/평가 기준도 유지된다.

현재 상대 링크 31개와 앵커 9개를 다시 확인했고 문제는 없다. 현재 X에 `quick_validate.py`를 한 번 실행해 종료 코드 0과 `Skill is valid!`를 확인했다. 변경 없는 helper 테스트, 이미지 생성·열람·편집, 새 점수·child·raw 재평가는 수행하지 않았다. 현재 12파일의 실제 경로·해시·크기, W와 다른 두 파일, 정확한 구절 복원 검사와 보존 기록은 `status.json`에 남겼다. 라이브·초안·raw·최초 감사는 이 재확인에서 수정하지 않았다.
