# 실제 카피로 미리 설계하는 구성 스케치

설명 문단과 일정·장소·참여 조건 같은 실용 안내가 함께 들어가 글자와 이미지의 면적을 조정해야 하는 요청에서는, 적합한 실제 글꼴과 기존 렌더러가 있으면 **최초 네이티브 호출 전에 새 코드 구성 스케치와 그 PNG 보기**를 작성한다. 실제 카피를 조판해 현재 표시 크기에서 필요한 문장 면적을 잡고, 선택한 이미지의 큰 관계와 함께 설계하는 짧은 디자인 작업이다. 무문자·제목만·간단한 카피에는 의무로 늘리지 않고 도움이 될 때만 사용한다. 기존 래스터나 반환 포스터를 편집하거나 새 승인·평가 단계를 추가하는 작업이 아니다.

사용자 지정 표현·배치·구도 보존을 우선하며, 현재 내용에서 선택한 관계·상태·경험을 관객 거리·대상 크기·연결·크롭·빛 등 이번 표현의 구체적인 선택으로 바꾼다. 스케치의 새 도형으로도 그 이미지 집합·경계·겹침·열림이 **실제 글자 덩어리와 함께 만드는 전체 큰 형태**가 드러나게 한다. 추상 표현도 내용의 관계가 형태·반복·대비와 글자 공간을 어떻게 조직하는지 그린다. 가장 가까운 방향과는 이미지의 조직과 카피의 형태·연속 관계를 함께 달리 설계하며, 같은 이미지 둘레의 빈 정보 면에서 첫 문구나 재료만 바꾸지 않는다. 도형은 선택한 이미지 관계를 설계하는 수단이며 최종 그림이나 사용자 보존 좌표가 아니다.

실제 확정 카피 전체를 현재 사용 가능한 적합한 글꼴로 조판한다. 사용자가 고정한 어절·기호·줄바꿈을 유지하고, 문단·실용 안내의 몸체·줄 폭·행간과 다음 묶음으로 이어지는 시작점·정렬·강약을 실제 글자로 선택한다. 출력한 PNG를 직접 보고 채택한 표시 크기에서도 읽는 면적과 큰 관계를 설계한다. 공간이 모자라면 조정 가능한 제목·이미지의 비중·크롭을 먼저 바꾼다. 고정 폰트·좌표·다섯 레이아웃·팔레트·정보 패널을 내장하지 않으며 내부 번호·영역 라벨 대신 실제 카피만 그린다. 본문 없는 요청에 새 본문을 넣지 않는다.

작성하고 실제로 본 로컬 PNG는 최초 호출에서 내장 이미지 도구의 **구성·글자 형태 참고**로 전달한다. 최종 포스터는 여전히 내장 image_gen으로 만든다. 명세에는 구현할 내용의 관계·시점·이미지 편집·색·마감과 참고할 읽는 관계·글자 형태를 함께 설명하고, 스케치의 빈 도형·회색·임시 표현 자체를 최종 스타일로 가져오지 않는다. 실제 사용자 참조·수정 대상은 빠짐없이 함께 전달하며 모두 포함하려면 계획 가이드의 도구 전달을 생략할 수 있다. 스케치의 크기·좌표·줄 수는 계획 선택이며 새 사용자 조건이나 중앙 승인 요건이 아니다.

가이드에서 실제 폰트 파일로 글자를 그렸다는 사실과 최종 래스터에 그 파일이 적용됐다는 주장은 다르다. 최종 카피·형태·판독·전체 관계는 반환 이미지에서 확인한다. 가이드의 좌표와 달라도 사용자 조건·판독·표현·방향 구분이 작동하면 계획 일치만을 위한 보정은 하지 않는다. 반환된 포스터의 글자를 Python·SVG로 덧씌우거나 원본을 재조판한 결과를 네이티브 이미지라고 부르지 않는다.

현재 선택한 계획 스케치의 파일·역할을 기록하며 요청한 완성 포스터 수와 구별한다. 이미지 도구의 최초/보정 호출 상한은 그대로 적용한다. 가이드를 썼다는 사실만으로 품질 통과를 인정하지 않고 불리한 최초 결과·미선택·불확실성을 보존한다. 적합한 글꼴·렌더러가 없거나 현재 문자를 지원하지 않으면 같은 실제 카피·읽는 면적·이미지 관계를 긍정적인 제작 명세로 구체화해 직접 생성한다. API·새 글꼴 설치·환경 설정·원작 재열람을 새 기본 단계로 넣지 않는다.

## 선택적인 실행 방법

기존 Python/Pillow 환경에서 [렌더러 계약](layout-guide-contract.md)의 실제 문구·선택한 폰트·도형 JSON을 사용한다. 스킬 위치의 `scripts/make_layout_guide.py`를 실행하되 현재 작업 디렉터리를 프로젝트 산출물 폴더로 둔다. 예: `python /설치된/ducttape-poster/scripts/make_layout_guide.py layout.json --output-dir guides --name direction-a`. 설치된 스킬 디렉터리로 이동하지 않는다. 입력과 새 SVG·PNG·명세는 호출한 작업 폴더 안에 두고 기존 파일은 덮어쓰지 않는다. 실제 사용 가능한 폰트 경로와 TTC face를 직접 선택한다. Python/Pillow 또는 적합한 글꼴이 없으면 설치·환경 설정 절차를 늘리지 않고 가이드를 생략해 제작 명세로 생성한다.
