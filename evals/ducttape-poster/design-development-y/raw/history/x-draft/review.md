# X 초안: 목적의 식별과 안내 경로를 최초 설계에 연결

현재 W의 12개 파일을 그대로 복사한 뒤 `references/production-brief.md`와 `references/parallel-production.md`의 생성 전 설계 문단만 좁게 수정했다. 나머지 10개 파일은 W와 바이트가 같다. X는 미채택·미시험 초안이며 진행 중인 R20 선택 평가와 무관하게 따로 보관한다.

근거는 닫힌 R20 최초 집계와 세 평가자의 최초 `.md`, 원본 coordinator 계획, root의 세 `root-initial-*.json` 관찰이다. 최초 집계는 원점수 105개가 있으나 editorial trace 오류로 절차 NA, 이미지 0 PASS / 0 FAIL / 5 NA, 전체 세트 NA다. 원관찰에는 M1의 행사/장소/서비스 정렬축 분산, M3·M5의 긴 설명 또는 일반 초대와 멀리 분리된 이름/행사, M2/M5의 큰 오른쪽 피사체와 위쪽 카피·아래 안내가 공유하는 구조, M4의 구역 간 안내 이동에 관한 서로 다른 의견이 남았다. 낮은 원점수와 높은 의견을 평균내거나 절차 NA를 품질 PASS로 바꾸지 않았다. 원자료를 읽은 것 외에 이미지 자체를 열거나 새 점수를 주지 않았다.

X의 변화는 실제 목적의 식별 정보·핵심 약속·다음 행동을 첫 읽기에서 연결하는 관계, 다섯 방향의 큰 이미지/카피 형태를 동시에 설계하는 관계, 실용 안내의 첫 줄부터 마지막 줄까지 실제 문장 면적과 사진 경계/정렬/다음 시작점을 함께 잡는 관계다. 초대·날짜·문단으로 시작하는 구성도 가능하지만 다양성만을 위해 그 비중을 키우고 이름·행사를 먼 별도 구역으로 떼지 않는다. 제목을 항상 가장 크게 하거나 같은 읽는 순서를 강요하지 않는다. 의도적인 구역 전환도 구체적인 전환 단서를 설계하며 한 열·패널·고정 순서로 통일하지 않는다. 주어지지 않은 약속이나 행동 카피를 추가하지 않는다.

W가 축적한 200개 아카이브 기사 이미지와 37개 스튜디오 이미지의 관찰 아이디어를 재사용하는 방식, 원본을 매 요청마다 다시 읽지 않는 방식, 복합 카피의 실제 폰트/문구와 내용 geometry 스케치를 최초 호출 전에 만드는 조건부 흐름과 지원되지 않는 환경의 명세 fallback, 최종 내장 네이티브 생성, 사용자 카피·스타일·자료·보존 범위와 독립 제작자 역할은 유지했다. 237개 자료를 독립 스타일/작품 수나 품질 증명으로 확대하지 않는다. helper·코드·평가 루프·기준·점수표·동시 실행 한도·보정 한도는 그대로이며 새 외부 검수자·픽셀 최소값·스타일 메뉴·추가 보정·새 20장 캠페인을 추가하지 않았다.

읽은 최초 관찰은 단일 요청의 개발 피드백이며 절차 NA와 평가자 차이가 남아 있다. X의 개선 효과·전이·보편적인 하이엔드 품질·AI 제작 주체·최종 폰트 파일 적용을 입증하지 않는다. 선택 평가 raw, 원본 출처 이미지, 이전 라운드는 이번 작업에서 읽지 않았고 라이브 W·round20·repo·선택본·원점수는 변경하지 않았다. X 채택·형식/동작 테스트·생성·추가 child 실행은 하지 않았다. 구체적인 지침 모순은 찾지 못했으며 고정 제목 우선이나 단일 경로로 좁히는 변경은 제안하지 않았다.

실제 변경 전후 해시와 나머지 10개의 동일성은 `changed-files.json`, 읽은 원자료의 해시·원 절차 상태·실행 범위와 한계는 `status.json`에 기록한다.
