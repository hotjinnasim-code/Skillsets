# Compact critic recording contract

Only metadata-only fixture jobs are created by verification. No real case preparation, critic, image, or actor is launched here. Declare and freeze this method together with the new runtime before any production. Use its exact frozen helper paths for both initial and selected review preparation.

Each of the three fresh independent critics would write one immutable `PROFILE.observations.json`. The critic supplies actual first-read text, separate layout observations, ambiguity/revisit, all mandatory judgments, seven integer scores and located evidence per image, and full-set diversity with evidence for every member. The adapter derives repeated identities, required-copy strings, normalization/equality, literal checked styles, packet dimensions, and standard JSON/Markdown presentation. It never derives a score, replaces an observed string with required copy, averages, drops members, selects critics, generates images, or edits native pixels. All existing v4 thresholds and procedural gates remain.

## Compact raw fields

The validated format is `schema_version:1`, `kind:"compact_critic_observations"`, the packet's `case_id/wave`, the assigned `profile`, `session_id:null`, and `packet:{path,sha256,bytes}`. Record all five image IDs exactly once in `images` and all fifteen attempted poster views in `viewed`, ordered by packet member then `native/usage720/thumbnail320`. Each view receipt contains `image_id,view,path,sha256,viewed`; an unavailable view has `viewed:false` and a reason. Preserve an unknown raw path rather than guessing a replacement. Actual missing views or mismatched bindings cannot become a successful viewing/order attestation.

`procedure` contains truthful `fresh_session`, `all_views_before_scoring`, `order_compliant`, `method`, `source_assets_viewed`, and `protected_layouts_read`. Sources and protected-layout manifests must be viewed/read before source fidelity judgments; all fifteen poster views precede the first judgment, image score, or set score. Receipts identify every exact pinned source asset (`asset_id,path,sha256,viewed`) and protected manifest (`manifest:{path,sha256},read`). An unavailable source/manifest requires a reason. Empty source arrays are explicit when no sources exist. These receipts are semantic attestations, not invented tool events.

Each image record contains:

- `copy`: one entry per required string, in packet order, with `raw` as the untouched actual first read (an empty string is allowed when nothing can be read), `layout:{status,observations}`, `ambiguity` as a description or null, and `revisit` as null or the existing one-revisit object (`view,path,sha256,raw_observed,resolved,reason,resolution`). First read is retained even after a resolved revisit. No required or normalized strings are written by the critic.
- `mandatory`: exactly `text/style/ratio/no_type_only/substantive_visual`; each includes the critic's actual `status:PASS|FAIL|NA` and any `issues`. Style, no-type-only, and substantive-visual include nonempty compact evidence. Text status must honestly match the retained reading, layout, issues, and ambiguity; the frozen summary checks this without adapter repair. The style judgment covers every literal condition and any applicable source identity/protected geometry, rather than maker intent.
- `ratings`: exactly the seven existing dimensions, each `{score,evidence}`. A score is an integer 1–5. An unjudgable value is `null` with a reason; v4 will preserve it and classify the affected record NA rather than inventing a number. Evidence is a list of `[view,location,observation]` tuples; even an unavailable judgment must locate the limitation honestly.
- `source_fidelity`: one `{asset_id,status,observations}` per source, explaining its user-assigned identity/style/composition role and any protected boundaries, relative position/size, and crop. Unknown/unviewed source pixels or unread protected geometry receive NA; definite observable violations receive FAIL. Required-source FAIL must appear in mandatory style FAIL; source NA cannot become style PASS. A style-only reference does not impose geometry it was never asked to preserve.
- `residuals`: concrete remaining limits, including low findings.

`set` contains the five ordered `members`, `count_fidelity:{status,observed_count,issues}`, the critic's independent integer `diversity` (or unjudgable null with a reason), `evidence` tuples `[image_id,view,location,observation]` covering all five, and `residuals`. These judgments are retained. Do not prefill scores or infer diversity from material labels.

## Dimensions, paths, and compatibility

All native dimensions and ratios come from the exact future packet; no portrait or 2:3 assumption is present. A landscape 16:9 poster is supported. `usage720` means width <=720 preserving aspect, without upsampling; `thumbnail320` means maximum edge <=320. The method does not create those views or resize images. The frozen summary independently verifies view/manifest/source hashes and PNG dimensions. If a raw return path or exact source cannot be located, preserve that missing binding and NA; do not recover it by newest-file scanning, a substitute crop, or another generation. Otherwise available pixels can still receive honest observations and low scores, while the unresolved provenance/source condition remains NA.

For a future declared run, pin this adapter and method instructions as launch inputs alongside the unchanged rubric/rules, packet, all exact poster views, supplied sources, and layout manifests. Inside each fresh critic session, first exclusively write its compact observation JSON, then call:

```sh
python3 compact_critic_adapter.py --packet EXACT_PACKET --observations PROFILE.observations.json --output-dir EXACT_CRITIC_DIRECTORY
```

The designated directory must already exist. The adapter exclusively creates `PROFILE.json` and `PROFILE.md`, refuses overwrites and incomplete member/evidence schemas, and binds the compact raw file and adapter hashes in the compatibility export. A future runner's expected outputs must include all three files so completion records their actual pins. No post-completion export, replacement pin, forged launch/trace, resume, fork, extra critic, or altered completion file is permitted. The existing v4 `--report PROFILE=PROFILE.json` consumes the declared compatibility export; its `raw_report` label refers to that export, whose metadata links the separate untouched observation record. It does not make the raw observation record disappear or turn derived fields into independent observations.

The existing v4 summary does not independently validate the adapter/raw-observation link or source-fidelity extension; future launch inputs/completion pins and the already required source-attestation audit must preserve those bindings. Adapter errors retain the original raw file and are procedural NA, not permission to edit it or rerun a critic. The future critic instructions must explicitly authorize its compact raw file plus two deterministic exports: the frozen R8 rubric's two-output instruction must not be silently reinterpreted.
