# Round 4 evidence tooling

Run `python3 evidence-validator.py --allow-incomplete` during production. Missing required evidence produces `INCOMPLETE` with exit 0; contradictions always produce `FAIL` with exit 1. Run without the flag for a completed audit: absent originals, native files, metadata, repairs already started, or final selection cause failure. The script reads files only and uses the Python standard library.

Call identities are exactly `production-c/ROLE/manifest.json`, `repair-1/manifest.json`, and `repair-2/manifest.json`. Every stage needs a role identifier, one native call count, recorded native input, positive dimensions, and explicit tool-source, preserved-original and final paths with SHA256. Paths resolve against that manifest's directory; no basename fallback or inferred artifact paths. All native copies must be byte-identical and use three distinct paths. Source aliases and nested `artifacts` metadata are supported; absent unsupported fields are reported, never guessed. PNG, JPEG and WebP headers are supported; this is not a full decoder or pixel inspection.

Accepted argument fields: `call_input`, `actual_call_input`, `actual_tool_input`, or `tool_call` (optionally nested `arguments`, `input`, or `args`). Initial C calls must omit both image-reference argument keys, even null/empty keys. Repair calls may use one mechanism. Each actual aspect ratio must be within 1% relative error of its role's case ratio. The fourteen roles are G01–G05, C01–C02, P01–P02, N01–N02, H01–H03 across six cases.

Final selection is required for strict completion. Preferred schema: `{"selected":[{"slot_id":"G01","final_native":"production-c/G01/final.png","sha256":"…","width":1024,"height":1536},…]}`. `items`, `selections`, or `finals` lists and the script's documented path/role aliases also work. Selection paths resolve against the round4 root and must match a final from that role's recorded C stage. Exactly fourteen unique finals, one per role, are required.

Optional round4 `call-ledger.json` uses `{"calls":[{"slot_id":"G01","stage":"initial","manifest_path":"production-c/G01/manifest.json"},…]}`. Repair stages are `repair-1`/`repair-2`. Every completed manifest must appear exactly once. Recorded total/cap fields recognized by the script are reconciled. Missing ledger is a warning because manifests remain the call accounting source; unsupported ledger schemas are missing required evidence. A ledger call pointing at an unfinished manifest stays incomplete and is never silently counted as a completed call.

The closed round3 ledger is pinned by SHA256, preserving its exact 34-call history. The report carries old per-role calls and prior-comparison calls separately from new C calls. Only each NEW C output has a two-repair allowance. Historical cumulative role totals may exceed two and are not capped at two. New phase cap is 42 and combined cap is 76. A manifest is evidence of a recorded call, not proof that no unrecorded tool call ever occurred.

This audit does not certify copy, typography, readability, style, diversity, image quality, native maximum resolution, review completion or the quality gate. Those remain separate located visual evidence. No image files are copied, resized, edited or generated.

The correction-wave2 input audit accepts the makers’ distinct optional reference-hash field names and compares every actual referenced file to its preserved parent manifest. Missing optional view/hash keys are reported as null, not inspection failure. This audit validates inputs and bytes; the makers’ actual inspection reports and independent blind reviews carry visual evidence.

The twelve terminal blank-line warnings listed in `planning/staged-whitespace-check.json` are preserved raw closed records, byte-identical to the original reviews/diagnostic file. No scores, findings or archived bytes were normalized. The normal staged whitespace check is clear for live skill, README and synthesized report; `git -c core.whitespace=-blank-at-eof diff --cached --check` checks all staged content for other whitespace errors. This exception does not alter repository Git configuration.
