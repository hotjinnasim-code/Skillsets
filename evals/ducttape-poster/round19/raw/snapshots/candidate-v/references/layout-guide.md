# 필요한 경우의 글자·구성 가이드

본문 면적·글자 골격·정보의 실제 위치를 말로만 정하기 어려우면, 선택한 실제 카피와 단순한 이미지 영역으로 **새 SVG 구성 스케치와 그 PNG 보기**를 먼저 만들 수 있다. 이는 코드로 만드는 계획 도형·글자이며 기존 래스터나 반환 포스터를 편집하는 작업이 아니다. 일반 제작의 새 승인·검수 단계나 모든 요청의 의무 산출물이 아니다. 본문 없는 요청에 새 본문을 넣지 않는다.

스케치에는 이번 방향에서 선택한 문구·줄 묶음·서체 형태·읽기 면적과 이미지/글자의 결합 관계를 보여 준다. 현재 사용 가능한 실제 글꼴을 선택하고 출력된 글자와 영역을 직접 본다. 고정 폰트·다섯 레이아웃·팔레트·정보 패널을 내장하지 않는다. 내부 번호·유형명·영역 라벨을 인쇄하지 않고 실제 카피만 넣는다. 글자 면적이 어긋나면 최초 생성 전에 이미지 크롭·형태와 글자의 관계를 함께 해결한다.

코드 스케치는 작성한 계획 자산이며 사용자 제공 포스터나 보존 조건이 아니다. 실제로 본 로컬 PNG를 내장 이미지 도구의 **구성·글자 형태 참고**로 전달할 수 있다. 최종 포스터는 여전히 내장 image_gen으로 만든다. 명세에는 구현할 이미지 표현·내용·색·마감, 참고할 읽는 관계와 글자 형태를 설명하고 스케치의 빈 도형·회색·임시 표현 자체를 최종 스타일로 가져오지 않는다. 실제 사용자 참조·수정 대상은 빠짐없이 함께 전달하고 이를 위해 계획 가이드를 생략할 수 있다.

가이드에서 실제 폰트 파일로 글자를 그렸다는 사실과 최종 래스터에 그 파일이 적용됐다는 주장은 다르다. 최종 카피·형태·판독·전체 관계는 반환 이미지에서 확인한다. 가이드의 좌표와 달라도 사용자 조건·판독·표현·방향 구분이 작동하면 계획 일치만을 위한 보정은 하지 않는다. 반환된 포스터의 글자를 Python·SVG로 덧씌우거나 원본을 재조판한 결과를 네이티브 이미지라고 부르지 않는다.

현재 선택한 계획 스케치의 파일·역할을 기록하며 요청한 완성 포스터 수와 구별한다. 이미지 도구의 최초/보정 호출 상한은 그대로 적용한다. 가이드를 썼다는 사실만으로 품질 통과를 인정하지 않고 불리한 최초 결과·미선택·불확실성을 보존한다. 글꼴/렌더러가 없거나 이 방법이 도움이 되지 않으면 긍정적인 제작 명세로 직접 생성한다. API·새 글꼴 설치·원작 재열람을 새 기본 단계로 넣지 않는다.

## 선택적인 실행 방법

기존 Python/Pillow 환경에서 [렌더러 계약](layout-guide-contract.md)의 실제 문구·선택한 폰트·도형 JSON을 사용한다. 스킬 위치의 `scripts/make_layout_guide.py`를 실행하되 현재 작업 디렉터리를 프로젝트 산출물 폴더로 둔다. 예: `python /설치된/ducttape-poster/scripts/make_layout_guide.py layout.json --output-dir guides --name direction-a`. 설치된 스킬 디렉터리로 이동하지 않는다. 입력과 새 SVG·PNG·명세는 호출한 작업 폴더 안에 두고 기존 파일은 덮어쓰지 않는다. 실제 사용 가능한 폰트 경로와 TTC face를 직접 선택한다. Python/Pillow 또는 적합한 글꼴이 없으면 설치·환경 설정 절차를 늘리지 않고 가이드를 생략해 제작 명세로 생성한다.
