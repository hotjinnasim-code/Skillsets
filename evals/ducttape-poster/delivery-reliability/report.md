# 포스터 답변 전달 절차 개선

GPT Work가 포스터를 제작한 뒤 이미지와 원본 다운로드 링크를 최종 답변에 누락한다는 사용자 보고에 대응했다. 선택 원본의 전달 레코드에서 **이미지 → 원본 다운로드 링크·픽셀 크기** 답변 블록을 준비하고, 중앙이 그 본문을 보내는 절차로 바꿨다. 새 포스터 제작·미적 평가·개별 이미지 보정은 수행하지 않았다. 누락률 감소나 실제 GPT Work 전달 성공을 측정한 결과는 아니다.

## 보고된 사례와 확인 범위

[사용자가 제공한 공유 대화](https://chatgpt.com/share/6ac88e75-7164-83ee-aa61-8d8cf9cfccc9?ogimg=plain)의 첫 번째 보이는 답변은 이미 스킬에 전달 지침이 있었지만 도구에 표시된 결과를 전달 완료로 잘못 판단했다고 설명한다. 이 설명은 제작 결과와 사용자 답변을 구분해야 한다는 수정 방향과 일치한다. 이전 누락 답변 자체, 최초 호출 문구·로드된 스킬 버전, 생성·인계 로그는 이 공유 사본에서 확인하지 않았다.

후속으로 받은 모바일 스크린샷에는 스킬 호출과 최초 답변이 보였다. 최초 답변은 시안 5종과 추천 스타일을 설명했으나 이미지·원본 링크가 없었고, 사용자가 재차 요구한 뒤에야 첫 포스터가 표시됐다. 따라서 최초 완료 답변의 누락 자체는 확인됐다. 로드된 스킬 버전·내부 생성 인계는 여전히 확인하지 않았다. [스크린샷 관찰 기록](raw/screenshot-case-observation.json)에 화면 범위와 해시를 남겼으며 스크린샷 원본은 로컬 작업 이력에만 보존했다.

익명 공유 화면에는 세 답변의 원본 PNG 다운로드 버튼 15개가 있었다. 화면의 이미지 영역은 회색 자리로 보였고 main의 렌더링된 `img` 요소는 0개였다. 다운로드 버튼은 실행하지 않았고 실제 파일 참조도 확보하지 못했다. 이 관찰은 원래 인증된 Work 대화의 렌더링 상태나 다운로드 성공을 입증하지 않는다. [관찰 기록](raw/shared-case-observation.json)에 방법과 한계를 보존했다.

## 변경

- 스킬 앞부분·호출문에 사용자 답변의 이미지와 원본 링크를 완료 산출물로 명시했다. 긴 호출문은 스킬을 활성화하고 제작 조건·전달 결과를 요청하는 한 문장으로 줄였다.
- 제작자별 선택 원본·표시 참조·원본 다운로드 참조·크기를 하나의 레코드로 인계한다. 제작자의 비공개 캐시·이미지 카드가 사용자에게 자동 전달됐다고 가정하지 않는다.
- [prepare_delivery.py](../../../skills/ducttape-poster/scripts/prepare_delivery.py)는 답변 본문과 전달 보고서를 준비한다. 누락된 참조는 미해결로 남기며 로컬 다운로드 파일이 선택 원본과 같은 바이트인지 확인한다. 출력은 덮어쓰지 않는다.
- 최종 답변에는 준비한 모든 시안 블록을 그대로 보낸다. 코드 실행·문자열 참조가 지원되지 않으면 실제 네이티브 이미지·파일 첨부로 같은 블록을 구성한다. URL을 만들어내거나 전달 실패 때문에 이미지를 재생성하지 않는다.

[전달 지침](../../../skills/ducttape-poster/references/delivery.md)에 로컬·대화 참조와 직접 첨부 경로를 구분했다. 기존 스타일 설계, 카피·타이포그래피, 사용자 수량 우선, 가용 동시 실행, 보정 한도는 변경하지 않았다. 공식 [스킬 자료](https://learn.chatgpt.com/docs/build-skills)와 [Work 시작 자료](https://learn.chatgpt.com/docs/get-started-with-work)를 참고했으나 특정 플랫폼 파일 URL 형식이나 보장되지 않은 첨부 API를 지침에 넣지 않았다.

| 스킬 frontmatter 검사 | PASS | 형식·필수 메타데이터 확인. 실제 스킬 수행 검증은 아님 |

검사한 도구 SHA-256은 `f9f3b9efa6a9fba884d37653c032a4167551bb07380b7c7e1aa2f17369a6878c`다. 최초 독립 실행은 43/44 PASS였다. 불투명한 스킴 없는 식별자도 Markdown 링크로 준비할 수 있다고 가정했던 한 사례는 차단됐다. 지원 범위를 명확히 해 그 참조를 직접 첨부 경로로 처리하도록 설명했고, 새 실행은 차단을 기대한다. 이전 점수·입력·결과는 [초기 기록](raw/forward-initial-summary.json)에 그대로 남겼으며 [새 실행의 경위](raw/forward-run-provenance.md)와 [최종 결과](raw/forward-final-summary.json)를 분리했다.

원래 fixture·선택 원본·미리보기의 해시와 바이트 수는 변경되지 않았다. 기존 이미지의 선택은 전달 시험 입력이며 디자인 합격을 새로 부여한 것이 아니다. 각 입력·명령·종료 코드·표준 출력·보고서·답변의 원문을 [초기 실행 묶음](raw/forward-initial-cases.json)과 [최종 실행 묶음](raw/forward-final-cases.json)에 보존했다. [회귀 출력](raw/regression-output.txt), [형식 검사](raw/format-checks.json), [최종 지침 검토](raw/instruction-final-resolution.md), [아티팩트 색인](artifact-inventory.json)이 추가 근거다. 독립 테스트 에이전트는 운영 코드·지침을 편집하지 않았다.

회귀 테스트는 저장소 루트에서 다음과 같이 실행한다. 별도 패키지·API 키가 필요하지 않다.

```sh
python3 -B -m unittest discover -s skills/ducttape-poster/tests -p test_prepare_delivery.py -v
```

## 실제 적용의 한계

`READY`는 답변 블록이 준비됐다는 뜻이며 사용자가 이미지를 보거나 다운로드했다는 뜻이 아니다. 도구는 읽을 수 있는 파일의 컨테이너·헤더·해시를 검사하며 전체 픽셀 디코딩을 하지 않는다. 대화 참조는 실제 환경이 반환한 값을 받아 보존할 뿐 원격 접근성·선택 원본의 동일성을 인증하지 않는다. 참조를 확보하는 책임은 중앙의 실제 원본 첨부 절차에 있다.

대화 참조 시험에는 명시적으로 모의 문자열을 사용했다. 갱신된 스킬을 실제 GPT Work에서 생성부터 인계·최종 답변까지 실행하거나 네이티브 첨부 대안을 시험하지 않았다. 스킬 지침·답변 준비 도구가 모델의 최종 발송 행동이나 플랫폼 표시를 강제한다고 주장하지 않는다. 저장소 변경을 기존 Work 대화·설치에 자동 적용한 것으로도 처리하지 않는다.
