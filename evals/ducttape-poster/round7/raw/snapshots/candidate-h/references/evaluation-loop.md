# 실제 산출물로 평가하는 루프

스킬 개선·비교·다중 에이전트 평가를 요청받았을 때만 읽는다. 아래 세 평가자 검증은 이 평가 루프의 절차이며, 일반 포스터 제작에 외부 평가·추가 승인·비용을 기본 단계로 넣지 않는다.

## 비교 설계

같은 원문 요청·필수 카피·참조 자료·수량·비율·보정 한도를 기존 버전과 후보 버전에 적용한다. 버전별 스킬 사본과 내부 프롬프트, 실제 출력, 보정 이력을 평가용 작업 폴더에 저장한다. 산출물은 스킬 폴더에 섞지 않는다. 사용자 요청에 이미 평가가 포함되면 그 범위에서 진행하며 새 비용·외부 변경의 권한을 자동 확장하지 않는다.

별도 제작자에게 해당 버전의 스킬, 원문 요청과 원자료만 준다. 예상 정답·의심하는 오류·개선자의 결론을 주입하지 않는다. 도구 호출에 성공한 실제 이미지와 계획만 수행한 사례를 구별한다.

다양한 요청에서의 품질을 개선할 때는 제목만 주어진 입력, 긴 안내와 참여 행동, 사진이나 그림의 제작 방식, 좁게 지정한 강한 스타일 등 서로 다른 제약을 포함한다. 제목만 주어진 입력과 글자만 있는 출력은 구별한다. 현재 개선 요청처럼 글자·여백만의 출력을 금지했다면 모든 평가 사례의 필수 조건에 그 금지를 넣고, 주제를 전달하는 이미지·장면·조형과 카피가 함께 작동하는지 확인한다. 작은 장식 하나를 추가해 금지를 우회하지 않는다. 먼저 생성한 전체 결과와 보정 후 선택을 구별하고, 동일 원문의 버전 비교와 새 지침으로 제작한 확인 사례를 기록한다. 일부 시안 보정만으로 최종 지침의 전체 성능이 검증됐다고 말하지 않는다.

병렬 제작을 바꿨다면 실제 협업 도구로 방향당 한 제작자를 실행해 전체 결과를 확인한다. 제작자 다섯 역할이 실행됐는지, 한 역할이 다섯 장을 다시 만들지 않았는지, 각 파일과 호출 이력이 독립적인지 확인한다. 논리적인 제작자 수와 실제 최대 동시 실행 수를 따로 기록한다. 도구 한도가 낮은 환경에서 나눠 실행한 결과를 다섯 명의 동시 실행 성공으로 부르지 않는다.

평가 전에 사례 목록, 버전, 요청별 전체 수량·역할, 필수 조건, 비교 규칙, 통과 기준과 실행 한도를 고정한다. 기본 다섯 방향은 다섯 장을 모두 제작·보존한 뒤 평가한다. 가장 좋은 일부만 보내거나 약한 요청·역할을 삭제하지 않는다. 사용자가 다른 수량을 지정했다면 그 전체 수량을 유지한다.

각 사례·단계의 완전한 결과를 서로 독립된 세 평가자에게 배정한다. 평가자는 버전·프롬프트·제작자 설명·동료 점수·목표 점수를 숨긴 식별자와 같은 원문·필수 조건·전체 결과를 받는다. 필요한 참조 원본은 함께 준다. 각 평가자는 전체 다섯 장의 원본·사용 크기·축소 보기를 모두 확인한 다음 개별 일곱 점수와 전체 세트 다양성을 기록한다. 일부 이미지만 보고 점수를 닫지 않는다. 열람할 수 없는 역할도 기록에 남기고 해당 판단을 NOT_ASSESSABLE로 표시한다. 첫 세트와 보정 후 선택 세트를 구별하며, 다섯 역할의 네이티브 SHA가 모두 같을 때만 최초의 완전한 세 평가 기록을 재사용한다. 하나라도 바뀌면 완전한 최종 세트를 별도의 독립 세 평가자에게 배정한다.

논리 역할 수·실제 동시 실행 수·새 세션과 재개 예외를 구분한다. 경로·해시·세션 기록은 출처 연결을 확인하지만 실제 의미적 이미지 열람·전사·순서의 증명이 되지는 않는다. 확인한 도구 사건과 평가자의 열람 진술을 별도로 남긴다.

## 필수 통과 조건

전체 카피의 문자·어절·문장부호 충실도와 사용 크기 판독, 지정 스타일·행동·참조 보존·비율·수량·독립 이미지 형식, 추가 카피·로고 등의 금지를 각각 확인한다. 해당 라운드의 글자·여백만 출력 금지도 필수 조건이다. 카피의 누락·변형·발명, 읽을 수 없는 필수 정보, 사용자 조건 위반과 확보하지 않은 실제 로고·화면의 정확한 재현 주장은 미적 장점으로 상쇄하지 않는다.

## 전사와 판독 불확실성

생성·평가 전에 다음 비교 방법과 보고 필드를 확정한다. 결과를 본 뒤 공백 규칙이나 equal 표기를 바꿔 통과시키지 않는다.

- **원시 관찰:** 이미지에서 실제로 읽은 문구를 줄바꿈·가시 간격과 함께 그대로 저장한다. supplied copy를 observed에 붙여 넣거나 이후 대조 결과로 원시 읽기를 덮어쓰지 않는다. 행동 정보의 카피 제공 전 전사를 요구하는 평가라면 전체 다섯 장의 정확한 사용 크기 자산을 먼저 보고, 첫 읽기를 저장·재조회한 뒤 원문과 대조한다.
- **문자 충실도:** 문자·어절 경계·문장부호 종류와 순서를 보존하는 비교를 한다. 대소문자·숫자·철자·문장부호의 차이를 임의로 교체하거나 모든 공백을 지워 일치시키지 않는다. 비공백 문자열이 같다는 검사는 원인 진단이며 그 자체가 필수 조건 PASS는 아니다.
- **배치와 광학 간격:** 사용자가 고정한 줄바꿈·공백은 그대로 비교한다. 고정하지 않은 줄바꿈은 판독된 어절 경계에서만 일반 단어 간격으로 정규화할 수 있다. 기호 주변의 광학적 간격을 문자 오류와 구별하려면 허용할 기호와 처리 규칙을 미리 명시한다. 그 규칙은 기호 자체나 단어 사이의 의미 있는 간격을 삭제하지 않는다. 배치로 생긴 줄바꿈·기호 주변 간격의 차이는 별도 layout 관찰로 남기며, 공백 차이만으로 글자 누락·맞춤법 오류를 만들어내지 않는다.
- **독립 필드:** required, raw_observed, 적용한 정규화 규칙, normalized_required, normalized_observed, 계산한 비교 결과, layout 관찰, 판독 ambiguity를 분리한다. equal은 정해진 정규화 결과에서 계산하고 보고된 Boolean과 대조한다. 관찰 원문·계산 결과·평가자의 불확실성을 서로 대체하지 않는다. 래스터 기호의 모양을 읽었다는 사실로 원래 Unicode 코드 포인트까지 인증하지 않는다.

필수 한글·어절·기호나 스타일·행동의 판독이 실제로 애매하면 위치·보기 제한을 적고 NOT_ASSESSABLE로 둔다. 해결을 위해 같은 경로·SHA의 정확한 원본 또는 사용 크기 자산을 한 번만 재확인할 수 있다. 최초 읽기와 재확인 읽기를 모두 보존하고, 여전히 애매하면 NA를 유지한다. 자산 재생성·크롭·보정·반복 조회로 좋은 판독을 얻을 때까지 시도하지 않는다. 명확한 조건 위반인 FAIL과 판독 또는 절차 부족인 NA를 구분한다.

## 시각 평가의 기준점

각 항목은 실제 보이는 근거를 하나 이상 적는다. 2와 4는 아래 기준 사이이며, 총점을 합산해 결함을 덮지 않는다.

| 항목 | 1: 미해결 | 3: 기능하는 결과 | 5: 매우 잘 해결된 결과 |
| --- | --- | --- | --- |
| 내용과 형태 | 다른 주제에도 그대로 쓸 상투적 구성 | 주제를 반영하지만 일부 선택이 임의적 | 구체적인 발상이 주요 선택을 연결하며 억지 해석이 없음 |
| 정보 계층 | 시선 분산·순서 혼란 | 중심과 읽는 순서가 보임 | 축소의 첫 시선부터 사용 크기의 참여 안내까지 자연스럽게 연결 |
| 타이포그래피 | 글자가 덧붙여진 느낌·불균일한 간격 | 판독과 그룹화가 합리적 | 획·줄 묶음·크기·간격·배치가 이미지와 하나의 구성으로 작동 |
| 공간 | 임의 마진·접촉·죽은 공간 | 전체 균형과 정렬이 일관됨 | 크롭·무게·여백·경계의 큰 관계와 작은 관계가 의도적 |
| 이미지와 재질 | 원근·빛·경계·질감의 혼란 | 표현 체계가 대체로 일관됨 | 원본에서도 재질·형태·마감이 발상에 맞게 정교하거나 의도적으로 거침 |
| 정서와 제어 | 효과·장식의 축적에 의존 | 요청에 맞는 정서와 요소 | 절제든 과잉이든 표현이 정확하고 각 요소가 역할을 가짐 |
| AI 슬롭 방지 | 상투적 패키지·글자·재질의 합성 흔적이 두드러짐 | 기술적으로 일관되지만 범용적인 습관이 남음 | 내용에 특화된 편집·글자·공간·재질이 설득력 있고 눈에 띄는 합성 결함이 없음 |

전체 결과의 다양성은 별도로 판단한다. 1은 색·필터만 다른 반복, 3은 구분되지만 구조적 습관이 남음, 5는 공통 조건 안에서 각 방향의 발상·글자 역할·공간·이미지 표현이 설득력 있게 나뉨이다. 최고 시안뿐 아니라 최저 시안과 전체 분포를 본다.

이 평가 루프의 **개별 이미지 PASS**는 필수 조건을 모두 통과하고, 독립된 세 평가자 **각각에게 일곱 항목 모두 4 이상**일 때만 부여한다. 내용과 형태·정보 계층·타이포그래피·공간·이미지와 재질·정서와 제어·AI 슬롭 방지 중 일부 항목만 골라 핵심 게이트로 삼지 않는다. **요청 세트 PASS**는 예정한 모든 이미지가 이 조건을 충족하고 세 평가자 각각의 전체 세트 다양성도 4 이상일 때다. 평균·최고 점수·평가자 다수결·다른 이미지의 장점으로 낮은 항목을 상쇄하지 않는다. 필수 자료나 유효한 평가가 부족한 경우는 NOT_ASSESSABLE이며 통과 또는 품질 실패 수에 섞지 않는다.

기본 스타일의 선호와 지정 스타일의 충실도를 나누어 본다. 스타일이 열린 요청에서는 범용 효과 패키지의 근거와 우선순위를 확인하고, 효과를 명시한 요청에서는 실제로 그 표현이 구현됐는지 먼저 확인한다. 둘 다 같은 주제·글자·마감 기준을 적용한다. 크롬을 쓰지 않았거나 아이보리 종이를 썼다는 이유만으로 높은 점수를 주지 않는다.

AI 슬롭 점수는 제작 주체 판별이 아니다. [아트디렉션과 마감의 검수 기준](art-direction.md)을 실제 위치와 근거로 적용하며, 특정 스타일이라는 이유로 감점하지 않는다. 이 항목이 3 이하이거나 평가자에게 구체적인 합성 흔적이 보이면 하이엔드 후보로 단정하지 않고 보정하거나 잔여 문제로 기록한다. 실행 중 새 기준이 필요해지면 원래 판정과 원시 자료를 고정하고 다음 후보의 평가 전에 선언한다. 기존 산출물에 적용한 추가 진단은 별도로 표시하며 원래 게이트를 덮어쓰지 않는다.

## 수정과 종료

실제 관찰한 실패를 가장 작은 유효한 지침 변경으로 고친다. 같은 요청을 다시 실행하고, 다른 내용이나 제약의 사례에서도 확인한다. 포스터의 한두 결함 때문에 스타일·색상·소재를 전면 금지하지 않는다. 국소 이미지 보정과 스킬 지침 개선은 기록에서 구분한다.

새 버전이나 보정본이 더 낫다는 전제 없이 전후를 비교한다. 일부 시안만 좋아지거나 새 결함이 생기면 그 사실과 선택한 최종본을 기록한다. 서로 다른 버전에서 최선의 시안을 고른 결과는 별도의 선별 결과이며, 한 버전의 전체 성능이 개선됐다는 증거로 사용하지 않는다. 독립된 대안 스타일을 요구한 평가에 요청하지 않은 캠페인 통일성을 통과 조건으로 추가하지 않는다.

평가 라운드와 도구 호출 수를 기록하고 실행 전에 유한한 범위를 정한다. **각 후보 버전·사례의 이미지마다 최초 생성 1회와 재생성을 포함한 자체 보정 최대 2회**를 지킨다. 중앙과 제작자의 호출을 합산하고 실패한 시도도 센다. 한도를 다 쓴 미통과·NA 결과는 그대로 닫는다. 버전 이름만 바꾸거나 동일 지침을 다시 실행해 보정 한도를 초기화하지 않는다. 좋은 결과나 우호적인 평가자가 나올 때까지 같은 후보를 무한 재추출하거나 유효한 낮은 평가를 교체하지 않는다.

사용자가 지속 개선을 요청한 경우에는 실제 실패 원인과 구체적인 스킬 변경을 기록한 새 후보로 다음 개발 라운드를 진행할 수 있다. 개발 사례의 관찰을 지침 개선에 사용한 사실을 공개하고, 매 라운드의 전체 결과·실패·NA와 한도를 보존한다. 종료 기준이나 원점수를 사후 완화하지 않는다. 전체 개선 작업의 계속 권한과 개별 후보·이미지의 유한한 호출 한도는 별개다.

개발과 전이 검증을 분리한다. 후보를 동결한 뒤 아직 제작·평가하지 않은 새로운 내용·제약의 사례로 뒤의 전이 검증을 수행한다. 보류한 사례와 세 평가자의 결과를 후보 개발에 미리 보여 주지 않는다. 동결 사례의 평가 피드백으로 그 버전의 이미지를 다시 생성·선별하거나 스킬을 바꾸지 않는다. 그 실패를 다음 개발에 쓰면 해당 사례는 개발 자료가 되며 이후에는 다른 미사용 사례를 보류한다. 알려진 실패를 고친 개발 결과만으로 새 요청에서도 통과했다고 말하지 않는다.

원시 이미지·선택·모든 미선택 보정·실패한 호출·평가자의 최초 관찰과 재확인·일곱 점수·세트 판단·절차 오류를 경로와 해시로 고정한다. 보고서의 역할/이미지/평가자 식별자, 원시 기록, 단계별 기록·점수 수와 PASS/FAIL/NA 분포를 같은 고정 자료에서 연결·재계산한다. 잘못된 집계나 전사 일치 표기를 NA 자료 보존 모드로 면제하지 않는다. 보고서 수정은 별도 이력으로 남기며 독립된 불리한 평가와 원시 관찰을 덮어쓰지 않는다.

모든 예정 요청의 개별 일곱 항목 게이트와 전체 세트 게이트를 충족했는지 보고한다. 한 이미지의 PASS나 동결한 몇 사례의 통과는 모든 요청·장르·향후 결과의 하이엔드 보장이 아니다. 평가자 사이의 차이와 판독 불확실성도 보존한다. 보고서에는 개발/동결 전이 구분, 실행한 모든 사례, 실제 이미지·보정·실패 수, 버전·파일, 남은 오류·NA와 검증하지 않은 범위를 남긴다. 소수 사례는 개선 신호를 보여줄 뿐 안정적인 성공률을 증명하지 않는다.
