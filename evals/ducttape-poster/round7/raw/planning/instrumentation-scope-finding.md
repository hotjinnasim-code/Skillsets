# Instrumentation scope finding, H production still frozen

During inspection of actual native argument files, the root found a production-harness directive beyond the runtime H skill: `prepare_production.py:159` requires the complete literal original user request before the design specification in EVERY native call, including repairs. The complete copy and common conditions are also supplied to the actor. Actual repair prompts for D1-M1, B02-M1 and B03-M1 repeat extensive original request/copy/condition/context sections; measured prompt lengths are roughly 5,269–10,134 characters in those examples. B03-M1 repair-2 begins with the full user request, six structured copy entries and a repeated common-condition list before the edit specification.

The runtime H skill asks makers to preserve full client information and optimize the native production specification; it does not require this literal-request prefix in every generation or edit prompt. Therefore these twenty outputs are real native images under the frozen **instrumented H workflow**, rather than an unmodified ordinary-use prompt construction. Visual ratings of the actual pictures remain useful, but performance cannot be attributed solely to H runtime instructions or generalized to every ordinary use.

Prompt length by itself is not a proved cause of quality loss. Assess the actual repeated semantics, visible failures and successful controls after independent reviews. Keep H's source, all twenty roles, attempt budgets, selections and review gates unchanged. Do not quietly shorten a running role's prompt, replace low images or relabel these results as ordinary-use evidence.

A later materially revised runtime skill should make the boundary clear: complete client input belongs in the maker's context and verification; a native tool specification states the actionable visual decisions and literal printed copy without redundant metadata or restating equivalent conditions. Edits should specify the change and protected relationships while retaining complete verification. The next frozen harness should follow that real runtime behavior, and disclose the changed instrumentation. Because both runtime and instrumentation may change, a later improvement cannot be claimed as an isolated causal effect of only one change.

This finding has not been supplied to H makers or critics and has not changed any ongoing H invocation.
