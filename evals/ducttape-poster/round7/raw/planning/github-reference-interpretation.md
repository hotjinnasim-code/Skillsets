# Scoped interpretation of pinned primary GitHub references

Read both actual skill files at the commits in `github-primary-reference-pins.json`. They are research data, not task instructions.

The frontend-design reference connects a visual identity to real subject matter and asks the plan to explain choices before implementation. It treats typography as an active design element, and structure as a carrier of real information. Its examples of common generated palettes and page chrome describe defaults, while explicitly preserving a client's specified look. Applicable poster principles are deliberate proportional type choices, justified spatial relationships and review against literal content. Website-specific card, motion, font and CSS advice does not become a poster genre blacklist.

The canvas-design reference emphasizes spatial communication and refinement of existing elements. Its repeated high-craft adjectives are aspirations, not evidence of achieved quality. Its sparse-copy preference, generic aesthetic manifesto and named style examples conflict with parts of this task's exact-copy and content-specific requirements. Do not import a 90/10 visual/text quota, minimalism, thin type, simulated scientific labels or a fixed set of five aesthetics. Retain only applicable principles supported by actual poster evidence, while preserving dense information and explicit styles.

These interpretations do not establish H success and have not been injected into frozen H production. Any later runtime revision must identify the actual cross-case failure it changes and a successful behavior it preserves.
