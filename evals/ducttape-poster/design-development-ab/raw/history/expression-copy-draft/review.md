# 표현·카피 최초 전달의 최소 초안

현재 LIVE AA 12개 파일을 drafts/candidate-expression-copy에 복사하고 SKILL.md와 references/production-brief.md만 수정했다. 아직 미채택이며 LIVE·helper·R23·케이스·계획·job·평가 문서는 이 작업에서 변경하지 않았다.

## 실제 차이

- 최초 native 명세를 **구현할 이미지 표현 → 실제 카피 한 벌의 조판 형태 → 장면·구도·색·마감과 조건**으로 전달하도록 맞췄다. 형태·경계·세부·빛을 만드는 표현 규칙이 장면·재료의 상세 선택·생략·변형을 조직하도록 했다. 같은 현실 장면에 질감 효과만 덧붙이는 방식으로 표현을 대신하지 않으며 필요한 사진 표현은 유지한다. 도시 소재나 특정 스타일 메뉴를 일반 규칙으로 만들지 않았다.
- 사용자 고정 줄바꿈이 없으면 원래 어절 경계의 공백을 선택한 의미 단위의 soft 줄바꿈으로 조판해 그 카피 한 벌에 담는다. 그 외의 철자·어절·숫자·기호·공백과 고정 줄바꿈은 유지한다. 원문 전체·그룹 JSON·같은 문장·역할 라벨을 중복 인쇄용으로 붙이지 않는다. 선택한 줄 수를 사용자 조건이나 결과 검수 문턱으로 만들지 않는다.
- 단순 카피에서도 실제 폰트·카피의 형태·면적과 이미지의 큰 면·선·경계를 함께 보이는 새 자기 저작 스케치가 명세를 구체화할 때만 선택적으로 쓸 수 있음을 명료하게 했다. 명세가 충분하면 직접 생성한다.

## 범위 보존

Title-only는 제목으로, Title+body는 그 두 실제 역할로 완결한다. 없는 eyebrow·Subtitle·footer·실용 안내를 만들지 않는다. 무문자와 사용자 비문자 제외도 존중한다. Title의 즉각적인 인지와 현재 광학 본문 면적 지침은 유지한다.

스타일의 정체성이 우선이고 좋은 읽기 구도는 공유할 수 있다. 다섯 레이아웃·매체·폰트·팔레트 차이를 강요하지 않았다. Title-only나 실용 안내 없는 Title+body의 복잡한 가이드 의무, 새 QA·증명표·승인·점수·픽셀·폰트·비율 하한을 추가하지 않았다. 설치·원작 재열람도 추가하지 않았다.

최종은 내장 imagegen이 문구를 포함한 전체 포스터를 만드는 기존 방식이다. 기존 래스터의 코드 편집·합성·글자 덧씌우기나 새 문서로의 전환은 없다. 초안 밖의 수치 범위 제안·normalization·evaluation·helper와 기존 기록은 그대로다.

## 확인과 한계

current12pins.json은 복사 시점 LIVE 12개 파일의 SHA-256과 바이트 수다. 수정 후 LIVE 전부가 이 baseline과 같고, 초안은 정확히 두 파일만 다르며 나머지 10개는 바이트 단위로 동일함을 대조했다. expression-copy.diff는 문맥 한 줄의 통합 차이다. 새 연결의 production-brief 섹션과 대상 문서가 존재하고 SKILL frontmatter는 원본과 같다.

skill-creator의 quick_validate.py는 기존 Python 환경에 PyYAML이 없어 ModuleNotFoundError: No module named 'yaml'로 시작 단계에서 실패했다. 설치나 검증기 수정은 하지 않았으며 검증기 성공을 주장하지 않는다. 별도 이미지·가이드·렌더·native 호출·새 라운드·critic·점수는 만들지 않았다.

이 문구 변경과 파일 범위 확인은 생성 품질을 증명하지 않는다. 이번 산출물은 검토할 런타임 초안이며 채택은 root가 결정한다.
