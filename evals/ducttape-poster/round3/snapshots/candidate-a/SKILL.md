# 덕테이프 포스터

사용자가 내용을 주면 서로 확실히 다른 다섯 스타일의 완성된 포스터 이미지를 직접 만든다. 기본 결과는 **스타일 다섯 개 × 스타일당 독립 이미지 한 장 = 총 다섯 장**이다. 사용자가 적은 디자인 조건을 다섯 장 모두에 반영하고, 나머지는 내용과 용도에 맞춰 모델이 결정한다. 문구 정확성뿐 아니라 주제에 맞는 시각적 발상, 글자와 이미지의 관계, 공간과 세부 마감까지 검수한다. 프롬프트는 이미지 도구의 내부 입력으로만 작성하며 프롬프트 제공 모드를 두지 않는다.

## 입력과 자동 디자인

- 자연어·메모·항목별 카피를 모두 받는다. 특정 양식을 요구하거나 비주얼·스타일을 선택하는 질문을 기본 단계로 넣지 않는다.
- 이미지에 표시할 문구와 제작 지시를 구분한다. "파란색", "큰 글자", "사람 없이" 같은 표현은 디자인 조건으로 반영한다. 항목명과 입력 구분자를 그대로 인쇄하지 않는다.
- 제목만 있어도 제작한다. 스킬만 호출하거나, 글자 표현을 요청했지만 표시할 문구가 전혀 없으면 필요한 문구를 짧게 요청한다. 텍스트 없는 포스터 요청은 그대로 제작한다.
- 사용자가 지정한 스타일·색상·소재·배치·제외 요소·비율·수량과 첨부 자료를 우선한다. 제작을 막는 누락이나 양립할 수 없는 조건만 확인한다. 선택 가능한 디자인 세부사항은 직접 결정한다.
- 고정된 스타일 목록·팔레트·레이아웃·프롬프트 템플릿을 따르지 않는다. 내용·대상·매체에 맞는 시각 전략, 정보 계층, 여백, 색상, 타이포그래피를 직접 설계한다.
- 요청한 비율을 우선하고 용도만 있으면 그 용도에 맞게 결정한다. 참조 포스터의 구도 유지를 요청했고 별도 비율이 없으면 해당 비율을 따른다. 아무 기준도 없으면 다섯 장 모두 세로 2:3으로 만든다.
- 새 포스터 제작은 다섯 스타일을 각각 한 장씩 완성한다. 사용자가 해당 제작에서 다른 총수량을 명시하면 그 수량을 우선한다. 여러 비율을 요청하면 정해진 총수량 안에서 배분하고 모든 스타일과 비율의 조합으로 개수를 자동 확장하지 않는다.
- 특정 스타일이나 여러 스타일의 혼합을 요청하면 그 조건을 공통 범위로 삼고 허용된 범위 안에서 다섯 방향을 충분히 구분한다. 스타일 차이를 만들려고 사용자가 지정한 조건을 버리지 않는다.
- 생성 직전에는 요청한 수량의 디자인 방향을 짧게 알리고 바로 제작한다. 별도의 스타일 선택이나 생성 승인을 요청하지 않고 요청한 장수를 모두 완성한다.

## 다섯 스타일의 구분

- 고정된 다섯 스타일 목록을 재사용하지 않는다. 생성 전에 다섯 방향을 함께 설계하고 매번 실제 내용과 사용자 조건에서 서로 다른 이미지 표현, 타이포그래피, 구성 원리와 공간 사용을 결정한다. 문구와 필수 대상·행동·정보는 다섯 장에 동일하게 유지한다.
- 각 방향에 주제를 어떻게 보이게 할지 한 문장으로 정하고, 그 발상을 구현하는 이미지 표현·구성 원리·글자의 역할을 함께 설계한다. 사용자 조건이 허용하면 주제 해석도 달리한다. 서로 다른 렌더링으로 동일한 구성을 반복하지 않는다.
- 처음 떠오른 방향을 즉시 확정하지 않는다. 필요한 경우 출력 수량보다 더 많은 후보를 내부적으로 비교해 **내용의 구체성, 제목의 조형적 역할, 사용 매체에서의 판독, 제작 논리, 다른 방향과의 차이**가 강한 후보를 고른다. 이 비교 때문에 실제 생성 수량을 늘리거나 사용자에게 선택을 맡기지 않는다.
- 색상·소품·크롭만 바꾸거나 같은 레이아웃에 효과만 바꾼 결과는 별도 스타일로 세지 않는다. 두 시안을 나란히 보았을 때 표현 체계와 시각적인 인상이 명확히 달라야 한다. 좁은 스타일 조건에서는 그 조건을 유지하면서 시점·공간 관계·정보 계층·타이포그래피 등 허용된 차이를 활용한다.
- 각 방향은 독립적으로 완성된 포스터여야 한다. 한 장 안에 다섯 스타일을 섞거나 번호·스타일명·비교용 설명을 작품 안에 인쇄하지 않는다.

## 디자인 판단

- 신규 제작이나 구도 재설계에서는 [아트디렉션과 마감](references/art-direction.md)을 읽고 적용한다. 그 문서는 스타일 목록이 아니라 내용에서 발상·구성·타이포그래피를 결정하고 실제 결과를 판단하는 기준이다.
- 스타일을 맡긴 요청에서는 주제보다 생성 효과가 먼저 보이는 범용 패키지의 우선순위를 낮춘다. 내용의 행동·구조·글자·매체에서 출발하고, 효과를 뺀 뒤에도 선택 이유가 남는 방향을 우선한다. 사용자 지정 스타일은 그대로 존중하며, 이 선호를 장르 금지나 고정된 새 스타일 목록으로 바꾸지 않는다.
- 하이엔드 완성도, AI 슬롭 방지, 적극적인 레퍼런스 조사를 요청받았거나 주제의 시각 언어가 불분명하면 [시각 자료 조사](references/visual-research.md)에 따라 실제 디자인 자료를 확인한다. 레퍼런스는 구성과 제작 원리를 이해하는 데 쓰고, 기존 작품의 카피·로고·특정 구도를 새 결과에 그대로 이식하지 않는다.
- 각 방향의 내부 명세에 **주제에 특화된 발상 → 첫 시선 → 이미지와 글자의 공간 관계 → 세부 정보로 이어지는 읽는 순서**를 연결한다. 재료·효과 목록이나 "하이엔드", "세련된" 같은 형용사만으로 디자인을 지시하지 않는다.
- 제목, 주된 장면, 참여 안내의 상대적 비중과 정렬·간격·경계·크롭을 함께 결정한다. 알려지지 않은 브랜드나 대상의 취향을 지어내지 않는다. 긴 카피는 의미 단위로 묶고 공간을 다시 배분하며, 작은 글자로 밀어 넣거나 삭제해 해결하지 않는다.
- 행사 이름만 바꿔도 그대로 쓸 수 있는 구성이라면 주제의 구체적인 특징을 더 드러낸다. 명료한 직접 표현도 좋은 발상이다. 억지 은유·새로움·미니멀리즘·화려함을 일괄 요구하지 않는다. 거친 질감과 복잡한 구성도 의도와 일관성이 있으면 유지한다.
- 제목을 이미지의 안전한 빈 곳에 놓는 것으로 끝내지 않는다. 글자의 비례·무게·줄 묶음·간격·기준선과 이미지의 관계를 설계하고, 정보가 많은 요청은 안내의 면적을 먼저 확보한다. 제목만 있는 요청도 질감이나 소품을 늘려 빈자리를 채우지 않는다.

## 이미지 제작

- 표시 문구를 확정한 뒤 철자·띄어쓰기·숫자·날짜·고유명사·문장부호와 지정된 줄바꿈을 보존한다. 명확한 필드 값이나 따옴표 안의 문구를 임의로 윤문·번역·축약하지 않는다.
- 사용자가 문구 작성까지 맡긴 경우에만 새 카피를 쓴다. 주어지지 않은 행사 정보·슬로건·인용·성경 구절을 지어내지 않는다. 승인되지 않은 장식 문자·가짜 로고·워터마크를 넣지 않는다.
- Codex 내장 `image_gen` 도구를 실제로 호출한다. 현재 세션의 도구 스키마와 사용 지침을 따르며 지원하지 않는 호출 인자를 만들지 않는다. API 키·SDK·CLI 실행을 기본 흐름에 넣지 않는다.
- 스타일마다 독립된 생성 호출로 포스터 한 장씩 만든다. 신규 생성에서는 공통으로 필요한 사용자 자료를 각 호출에 전달하되, 먼저 생성한 시안을 다른 스타일의 기준 이미지로 자동 이월하지 않는다. 각 호출이 하나의 평면 포스터를 만들도록 명시한다.
- 생성·수정마다 내부 제작 명세에 **"요청한 화면 비율을 유지하면서 현재 도구와 모델이 지원하는 가능한 최대 해상도로 출력"**하도록 명시한다. 단순히 "고화질"이라고만 적지 않는다. 사용자가 특정 픽셀 크기나 낮은 해상도를 명시한 경우에는 그 요청을 우선한다.
- 해상도 설정을 제공하는 도구라면 요청한 비율에서 지원하는 최대 설정을 사용한다. 크기를 지정하는 호출 인자가 없으면 최대 해상도 요구를 프롬프트로 전달하되, 그 요구가 실제 출력 크기를 제어하거나 최대 해상도를 보장하지는 않는다고 판단한다. 지원하지 않는 인자를 추가하거나 API의 해상도 상한을 내장 도구의 보장값으로 취급하지 않는다.
- 픽셀 수를 키운 리사이즈를 원본 생성 해상도나 새로운 세부 묘사로 취급하지 않는다. 사용자가 요구한 크기를 제어할 수 없으면 실제 반환 크기와 그 한계를 알린다. 확인할 수 없는 최대 크기를 얻으려고 생성을 반복하지 않는다.
- 사용자 요청을 충실히 담는 제작 명세를 내부적으로 최적화한다. 명세를 사용자에게 출력하는 것으로 이미지 생성을 대신하지 않는다.
- 입력 이미지를 사용할 때는 실제 파일 또는 대화 이미지를 도구에 전달하고 역할을 구분한다. 스타일이나 구도만 참고하는 기존 포스터의 행사 정보는 새 포스터에 옮기지 않는다.
- 현재 도구의 참조 방식에 맞춘다. 로컬 참조는 먼저 실제로 열어 확인하고, 파일 경로로 전달할 수 없는 자료는 대화 이미지 참조 방식으로 전달한다. 이전 시안의 자동 이월을 막으려고 사용자 참조까지 누락하지 않는다. 모든 필수 이미지를 전달할 수 없으면 누락된 자료를 확인한다.
- 실제 화면이나 로고를 보여 달라는 요청에서는 제공된 파일·URL·접근 가능한 프로젝트 자료로 원본을 먼저 확인하고 도구에 참조 자료로 전달한다. 원본을 확보하지 못했으면 모사 이미지를 정확한 재현으로 전달하지 않는다.
- 각 결과는 문구와 디자인이 함께 들어간 단일 평면 포스터로 만든다. 다섯 장을 한 이미지의 패널·콜라주·콘택트시트·목업으로 합치지 않는다.

## 확인·수정·전달

- 생성 결과를 실제로 보고 문구 일치·누락·추가·중복 문자, 잘림·겹침·가독성, 사용자 디자인 조건과 비율을 확인한다. **축소 보기에서는 첫 시선과 전체 형태, 사용 크기에서는 정보 계층과 읽는 순서, 원본 크기에서는 한글 획·간격·정렬·경계·재질**을 확인한다. 필수 세부 정보는 실제 사용 크기에서 읽혀야 한다. 용도를 모르면 화면에서 확인한 범위를 기준으로 말하며 인쇄 적합성을 단정하지 않는다.
- 문구가 정확해도 장식의 중복, 서로 어울리지 않는 표현, 내용과 무관한 상투적 구성이 보이면 디자인 수정 대상으로 삼는다. 인물·소품이 있는 경우에는 손·물체 구조와 요청한 표현에 맞는 피부·재질도 확인한다. 실제 화면이나 로고를 요청했다면 확인한 원본과 비교하고 생성한 모사 화면을 정확한 캡처라고 주장하지 않는다.
- 생성한 결과를 서로 비교해 색상 변경 수준의 유사한 시안이 있는지 확인한다. 충분히 구분되지 않는 시안은 해당 방향의 이미지 표현·타이포그래피·구성 원리를 재설계하여 수정한다. 기본 제작에서는 한 장의 완성도가 높아도 나머지 네 장의 제작을 생략하지 않는다.
- 반환 파일이 있으면 실제 너비·높이를 확인하고 최종 전달 시 픽셀 크기를 함께 알린다. 최대 설정 적용이 확인된 경우에만 그 사실을 알리고, 프롬프트로 요청한 것만으로 최대 해상도를 달성했다고 말하지 않는다.
- 검수에서 **문구·조건 위반 → 읽기와 구성 → 글자·이미지 마감** 순서로 영향이 큰 원인을 고른다. 국소 문제는 기존 이미지를 참조해 수정하고, 발상·구성이 실패한 방향은 원인을 반영해 재설계한다. 수정 명세에는 바꿀 부분과 유지할 부분을 명시한다. 자동 보정은 재생성을 포함해 이미지당 최대 두 번이며 매번 전체 카피·조건과 결과를 다시 본다. 문구를 삭제하거나 장식을 쌓아 해결하지 않는다. 확인되지 않거나 해결되지 않은 부분은 구체적으로 알린다.
- 보정 전후를 직접 비교하고 가장 적합한 결과를 선택한다. 새 보정이 글자 대비·판독·주제 연결이나 기존 장점을 떨어뜨리면 최신 파일이라는 이유로 채택하지 않는다. 더 좋은 이전 결과를 유지할 수 있으며, 어느 결과도 필수 조건을 통과하지 못하면 남은 문제를 알린다. 검수 기록과 최종 파일의 대응을 실제 선택에 맞춘다.
- 문구와 필수 조건의 위반은 미적 장점으로 상쇄하지 않는다. 주제 표현·정보 계층·타이포그래피·공간·이미지 마감 중 분명히 미완성인 부분이 있으면 다음 보정의 대상으로 삼는다. "하이엔드"라는 프롬프트나 자기 점수만으로 완성도를 주장하지 않는다.
- 전체 수량 중 가장 약한 시안까지 같은 기준으로 본다. 문구가 맞는 기능적 결과에 머물러 있으면 전달 전에 남은 보정 범위에서 원인을 고친다. 제목·주제의 연결을 지우고 표면만 매끄럽게 만드는 보정은 개선으로 세지 않는다. 한도 안에서 해결되지 않은 결과는 완료 수량에 포함하되 남은 결함을 숨기거나 하이엔드라고 포장하지 않는다.
- AI 슬롭 방지를 독립적인 품질 기준으로 삼는다. 상투적인 발상·임의 장식·가짜 미세 문자·어색한 한글·붙여 놓은 글자·일관성 없는 재질과 빛 등 실제 흔적을 찾고 원인을 고친다. 특정 색·효과·사진·3D라는 이유만으로 탈락시키지 않는다. 판정은 눈에 보이는 완성도에 대한 것이며 제작 주체를 식별했다고 주장하지 않는다.
- 후속 변경에서는 사용자가 지정한 이미지와 부분만 바꾸고 나머지 문구·디자인을 유지한다. 한 장의 부분 수정 요청을 새 다섯 장 제작으로 확장하지 않는다. 날짜 일부 변경은 기존 시간·장소 등 다른 정보를 보존한다. 결과를 대상 원본과 직접 비교해 글자뿐 아니라 구도·빛·질감의 비의도 변화도 확인한다. 해결되지 않은 변화가 있으면 "나머지 그대로"라고 단정하지 않고 구체적으로 알린다. 대상이나 변경 범위가 불명확할 때만 확인한다.
- 사용자 지정 경로 또는 프로젝트 산출물 폴더에 실제 결과 파일을 저장한다. 원본은 보존하고 기존 파일과 충돌하지 않는 이름을 사용한다. 각 스타일의 최종 파일을 개별 저장하고 기본 제작에서는 다섯 개의 최종 이미지가 있는지 확인한다.
- 방향별 원본과 선택한 최종 파일의 대응을 유지한다. 보정으로 파일이 늘어도 최종 전달 수량은 사용자가 요청한 수량이다. 수정된 시안과 폐기한 원본을 별도 스타일로 세지 않는다.
- 채팅에 최종 이미지를 각각 보여주고 각 파일의 다운로드 링크를 제공한다. 기본 제작은 다섯 이미지를 모두 전달한다. 번호와 스타일 설명은 이미지 밖에 짧게 적는다. 설명은 디자인 방향과 실제 남은 문제만 짧게 적으며 내부 프롬프트·API 설정·진단표를 붙이지 않는다. 후속 수정에서는 수정한 결과만 전달한다.
- 도구가 없거나 실패하면 실제 상태를 알린다. 생성하지 않은 이미지, 존재하지 않는 파일, 수행하지 않은 검증을 완료했다고 주장하지 않는다. 이미지 블록만 반환됐다면 이미지를 보여주되 파일로 저장했다고 말하지 않는다.

## 스킬 평가 요청

사용자가 스킬 개선·비교·다중 에이전트 평가를 요청했을 때는 [평가 루프](references/evaluation-loop.md)를 읽는다. 일반 포스터 제작에 평가 보고서나 외부 평가자를 기본 단계로 추가하지 않는다.
