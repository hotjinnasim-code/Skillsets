# 광학 본문 설계 초안 검토

현재 LIVE Z의 12개 파일을 drafts/candidate-optical-body에 그대로 복사한 뒤, references/production-brief.md의 본문 설계 문단과 필요한 references/layout-guide.md 문구만 수정했다. LIVE 채택, 새 케이스·계획·제작·평가는 수행하지 않았다. 전체 R22 최초·선택 평가가 닫힌 뒤의 채택 판단은 root가 맡는다.

## 변경 이유와 범위

명목 폰트 크기와 계획 면적 안에 카피가 들어가는 사실만으로 실제 표시 상황에서의 편한 읽기를 보장할 수 없다. 최초 설계에서 현재 서체의 한글·라틴·숫자 몸체·속공간·획과 대비를 보고, 필요한 설명·안내의 문장 면적부터 선택하도록 기존 “본문 먼저”를 구체화했다.

이 면적과 함께 Title의 어절·폭·크기·무게·대비·여백과 이미지의 거리·크롭·열림을 조정한다. Title은 즉시 제목으로 인지되는 주된 앵커를 유지한다. 본문이 커졌다는 이유만으로 Title을 같은 배율로 늘리는 자동 대응을 두지 않는다. Title에 필요한 별도의 크기 조정 자체를 금지하는 문구는 아니다.

layout-guide는 이미 하는 한 번의 전체 PNG 보기에 채택한 표시 크기를 사용해 실제 문장의 읽는 면적과 큰 관계를 설계하도록 맞췄다. 새로운 보기·증명표·측정 항목·검수 통과 조건을 만들지 않았다.

## 보존한 사항

- 다섯 스타일의 정체성이 우선이며 좋은 읽기 구도·정렬은 공유할 수 있다.
- 실제 공급 카피의 역할만 설계한다. Title-only와 실용 안내가 없는 Title+body에 복잡한 가이드를 의무화하지 않는다.
- 최종은 내장 imagegen이 문구를 포함한 전체 포스터를 생성하는 기존 방식이다. 반환 래스터의 코드 합성·글자 덧씌우기나 새 문서 방식으로 전환하지 않는다.
- 고정 본문 픽셀·폰트·Title/body 비율, 추가 QA·지표·새 source 열람·설치를 요구하지 않는다.
- helper 코드와 나머지 10개 파일은 LIVE와 바이트 단위로 같다. normalization·evaluation 문서와 기존 수치 예시·일곱 기준·점수 하한은 변경하지 않았다. 별도 대기 중인 수치 범위 제안은 반영하지 않았다.
- 원본 Z, R22, 기존 평가·원관찰 기록과 Git는 이 작업에서 수정하지 않았다.

## 확인과 한계

current12pins.json은 복사 시점 LIVE 12개 파일의 해시·바이트 수를 기록한다. 수정 후 모든 LIVE 파일이 이 해시와 같은지 대조했고, 초안에서 달라진 파일이 정확히 두 문서인지 확인했다. optical-body.diff는 그 두 파일의 실제 통합 차이다. 이는 변경 범위를 확인하는 검사이며 이미지 품질 판정이 아니다.

skill-creator의 quick_validate.py를 기존 Python으로 실행했으나 PyYAML이 없어 ModuleNotFoundError: No module named 'yaml'로 시작 단계에서 실패했다. 일반 python3도 같은 의존성이 없었다. 패키지를 설치하거나 검증기 코드를 바꾸지 않았으며 quick_validate 성공을 주장하지 않는다. SKILL.md의 frontmatter·메타데이터와 문서 연결은 이번 수정의 대상이 아니고 원본과 동일하다.

새 포스터·가이드·렌더·native 호출·critic·점수를 만들지 않았다. 최초 생성 효과는 이번 문구 수정이나 해시 대조로 인증할 수 없고, 이 초안은 아직 미채택이다.
