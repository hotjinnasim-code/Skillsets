# Candidate I behavior and harness audit before one five-image request

This is a static audit of the unfrozen draft and proposed execution instructions, written before generation. I read all six files under `drafts/candidate-i`, all of `prepare_production.py`, `planning/single-five-case.json`, and `coordinator/R8-C1/plan.json`. I also read the existing design audit and narrow supporting excerpts of `review_rules.md` and `evidence_io.py` to check transcription and QA-view conventions. I did not run the preparer, its self-test, a maker/critic runner, an image call, or an agent; inspect H critics or credentials; or view reference/generated pixels. Only this audit file was written.

## Decision and necessary fixes before freezing

The candidate's written behavior retains the requested five maker roles, available-concurrency execution, whole-system studio/Canva research, distinct-direction planning, exact-copy review, whole-image/set QA, bounded corrections, and deliberate before/after selection. It does not make a twenty-image campaign the next step. The current case is suitable for one development request after the following focused fixes. These are instruction findings, not image-quality findings or runtime verification.

1. **Complete each direction's nine-entry copy-role map.** All nine strings are present, unchanged, in the case and coordinator `copy` arrays and in every direction's `fullcopy`. No source-level copy omission or invented printable text was found. Nevertheless, the short layout descriptions leave the descriptor/free participation implicit in M1; descriptor/free participation/invitation implicit in M2; activity/free participation/invitation implicit in M3; and descriptor implicit in M4. A full-copy dump does not assign those entries a meaningful reading role. Add a compact map covering every entry once, with event identity and free participation legible rather than delegated to small-print defaults. Do not give every maker identical boxes or positions.

2. **Replace the harness's unqualified “No panels.”** `prepare_production.py`'s native-generation paragraph forbids panels, while M5 intentionally uses three narrative frames and M4 uses distributed modules inside one poster. Forbid multiple poster designs, comparison panels, contact sheets, room/frame mockups, and extra experiment images in one output. Explicitly allow content-based scene frames and image/information modules inside the one requested independent poster. This distinction should apply to the actual native spec as well as the maker context.

3. **Correct the development status.** The case calls itself `single-five-frozen-transfer-after-H-development`; the plan says unfrozen and both audits inform pre-generation changes. Label this as candidate-I development of one five-image request. Freezing inputs for this run is an execution-control step, not held-out transfer validation. Root has already acknowledged this correction. Keep the five members and finite call budget; evaluate this complete request and record any generalizable revision before another request.

4. **Make reference-geometry preservation conditional on the asset's user-assigned role.** The preparer currently tells every maker to preserve all “supplied reference geometry and measured_layout.” The skill itself correctly distinguishes an edit target, composition reference, style reference, and actual subject. Require geometry/layout preservation only where the user requested that relationship. A style reference supplies relevant visual principles without automatically fixing its objects, layout, or crop; research artwork is not a client preservation asset. This case has no client assets, so its actual run will not test that boundary.

5. **Define retries after failed native calls.** The preparer tells every repair to pass an exact prior returned image. After an initial failure there is no returned target. Specify a bounded fresh retry when no own image has returned, preserving all required client assets and the failure record. After an intervening failed repair, a new edit should reference the last actually returned, inspected own target. Keep immediate-attempt parent/failure provenance separate from the visual target used for before/after comparison. Do not fabricate a path or reset the three-attempt limit.

6. **Use explicit current production inputs.** The CLI still defaults to `planning/corpus20.json` and `snapshots/candidate-h`. It requires explicit case selection, so it does not automatically schedule twenty cases; nevertheless, those stale defaults can prepare the wrong candidate or fail on this new case. Before execution, require or provide the single-five corpus, R8-C1 case, frozen candidate-I snapshot, and intended fresh output directory explicitly. Pin those exact inputs. Changing safe defaults or requiring the corpus/candidate flags is preferable for future reuse.

7. **Expose the current concurrency ceiling and actual evidence.** The skill calls for five logical maker roles and execution at the actual available limit. `max_worker_concurrency:3` is consistent with a four-slot collaboration environment when the coordinator occupies one slot. It is a declaration, not proof that three native calls overlap or that all five makers finish. Record the resolved capacity, five role executions, scheduling of remaining roles, and real caller start/end intervals. If capacity differs at launch, use the current allowed ceiling; do not silently keep a historical cap or use separate sessions to bypass one. This audit launched no makers and verifies no concurrency outcome.

## Protections to retain and limits of verification

**Focused native input.** `SKILL.md`, `parallel-production.md`, `evaluation-loop.md`, and `maker_prompt()` expressly distinguish complete maker understanding from a focused image-tool production spec. The wrapper presents the original request and copy JSON as verification context and explicitly says they are not a compulsory prefix. It asks for printed copy once in the initial spec, relevant user constraints, and concrete whole-image decisions; repairs specify observed changes and protected relationships. Thus the present harness does not require the earlier duplicated request/JSON native input pattern. Actual `call-input.json` records must still show that the maker followed this boundary without omitting copy, actions, or required asset conditions.

**User authority and ordinary workflow.** The skill honors explicit count, ratios, narrow styles, source-image roles, fixed line breaks, and authorized copywriting boundaries. Multiple ratios are allocated within the requested count. Title-only inputs proceed, text-free requests are respected, and optional design choices do not trigger questions. One-image edits apply to the specified image/part, require actual target reference and a comparison of preserved areas, and do not trigger a fresh five. No forced clay/paper/minimal/campaign roster or extra approval step was found. The preparer's metadata validation accepts N>=1 and requires matching role/direction counts, but this audit did not run N=1/N=3 fixtures or a one-image edit.

The harness's maximum-resolution sentence should repeat the skill's explicit precedence for user pixel sizes or lower-resolution requests. Its ratio paragraph already says rounding tolerance never overrides pixel-size instructions, but that does not by itself qualify an unconditional maximum-output instruction. For R8-C1 there is no pixel-size override, so retaining the maximum-supported-output request and measuring the actual return is appropriate. Neither a prompt sentence nor later resizing establishes native maximum resolution.

**References, diversity, and AI slop.** The candidate requires actual studio images plus relevant Canva templates and covers imagery, crop, color, layout, information, typography, material, and emotion together. It lowers repeated clay/complement/toy and large-title/large-object/footer packages while permitting justified expressive media. It expressly resists replacing them with a quiet paper/minimal default. The five planned organizations are distinct in text: continuous scene, crossing exchange, joined surface, distributed catalogue, and sequential story. Their implementation and set diversity remain unverified until all five images are viewed. Preserve the design audit's focused hierarchy revision and compare actual large forms, type roles, information paths, and nearest-pair overlap after generation. A repeated Canva observation under five roles is context, not proof of five distinct solutions or successful accessibility.

**Whole-image QA and exact copy.** The skill requires original, use-size, and thumbnail inspection, full-copy fidelity, meaningful nonglyph content, user constraints, local finish, and complete-set inspection including the weakest member. The preparer records every returned stage, actual view paths, raw observed text, separate normalized comparisons/ambiguities, and concrete residuals. The checked helper excerpt defines `usage720` as width <=720 with aspect preserved and no upsampling; `thumbnail320` has long side <=320. For a sufficiently large 2:3 return the intended use view is 720×1080, not a 720-pixel long edge. Retain this convention before generation. The source image must remain byte-identical; these QA reductions are viewing aids, not production edits. Helper records and a maker's view attestation do not independently prove semantic inspection.

**Corrections and selection.** Each image has one initial attempt plus at most two corrections, including failures and coordinator calls. Actual originals, failed calls, input evidence, inspections, and unselected returns are preserved. The written workflow compares returned stages and chooses the result that best retains content/readability/earlier advantages instead of automatically taking the newest. Selection closure precedes independent critics; a returned but unsealable image is incomplete, not an invented all-failed role. Retain the distinction between immediate attempt provenance and visual comparison when a failure intervenes.

**One complete request before the next.** The evaluation reference and current policy retain all five members, complete initial/selected sets, independent complete reviews, low findings, finite calls, and exact-context conditions for review reuse. `review_rules.md` and the case policy explicitly require the entire evaluation context as well as all native hashes to match; keep that wording when interpreting the evaluation reference's shorter hash condition. Generalizable changes may follow this development request. No next twenty-image campaign, transfer claim, model-quality score, success-rate estimate, or universal quality guarantee is supported by this audit.
