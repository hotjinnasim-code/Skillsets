## Remaining concrete blockers

1. **Source-audit observed claims still block NA preservation.** `archive_single_five.py:37–46` includes `source-asset-audit.json` among authoritative documents, but only filters raw claim subtrees from summaries and skips maker inspections/comparisons. The source-audit profiles also retain `observed_source_assets_viewed` and `observed_protected_layouts_read`. A report with an extra/wrong source path/hash correctly yields source-attestation NA, which the updated sealer now retains; recursive `pinned_objects` still resolves and verifies that observed claim at `46–51`, rejecting preservation. Exclude those two observed subtrees from authoritative traversal while retaining their exact raw bytes and genuine packet/report pins. This also matters in this no-client-assets case: an extra claimed source is an invalid observation, not a new authoritative asset.

2. **Unmapped raw viewed paths still resolve against original-host metadata.** `verify_archive.py:52–70` wraps the frozen engine's digest and JSON reads, but leaves its `resolve` function unchanged. The earlier inspected frozen viewed-record check calls that resolver on the raw observation; an unmapped absolute path returned unchanged by `alias(..., observational=True)` at `60–61` therefore still reaches `Path.resolve(strict=True)` on the original host. A relative traversal claim can do the same. Add an in-memory resolver barrier before any host filesystem resolution: authoritative paths must resolve through the archive; unmapped observation identifiers must fail resolution and remain literal invalid claims so v4 reproduces NA. Do not access original-host metadata merely to decide that the observation is invalid.

3. **Exact wave/case topology and unready-state claims remain unverified.** `verify_archive.py:74–82` iterates whatever wave/case keys final evidence contains. It does not require exactly `initial` and `selected`, exactly the pinned corpus case in each wave, or compare an unready item's stored readiness state/reasons with the claim. Empty `stages`, or empty `cases` in a wave, can skip all replay and pass when final session/count fields are zero. A byte-pinned READY readiness record can likewise be labeled unready NA and skipped. Require the exact wave/case topology and validate the corresponding readiness's UNREADY state, retained five-member identity, and reasons before skipping replay. On the sealing side, `seal_single_five.py:99–105` uses the global readiness state but pins the separate per-case readiness document without checking that they agree; bind these two views of the same state. For ready/reused phases, also assert the stored summary's case/wave identity, allowing the initial summary only for explicitly bound whole-case reuse.

4. **Caller/source agreement is still a substring test.** `seal_single_five.py:86` checks `source['path'] in json.dumps(caller)`. A source path mentioned in unrelated caller text, or as a prefix of a different returned path, satisfies this without being the explicit returned source identifier. Compare the manifest source to the typed explicit returned-path field/list from the preserved caller record using exact string equality, and retain an unsealable status if that recorded return representation is absent or ambiguous. Keep the raw caller record unchanged.
